# 약관·고지 관리

약관·개인정보처리방침·동의·고지·신고 접수 절차를 정비하기 위한 기준 문서임. 항목별 현황, 보완 작업, 선행 결정을 한곳에 모음. 진행 상태는 이슈에서 추적함.

- 작성 기준일: 2026-11-04
- 현황 기준: `develop` (`ca99fd6`, 구글 로그인·온보딩 가입·회원 관리 반영)
- 법령 내용은 2차 자료를 바탕으로 한 참고용임. 원문과 소관 기관 확인 후 확정함.
- 상태 표기: 구현됨 / 초안 / 보완 / 결정 필요 / 확인 필요

## 0. 전제로 한 결정

- 신고 자동 임시 비공개: 런칭 초반 서로 다른 회원 4명 이상
- 이미지 업로드: 1차 연동에서 S3로 구현함. 용량을 넘는 이미지는 브라우저에서 자동 압축함.
- 관리자 페이지: MVP에 포함함. 신고 처리 대기 건수를 확인하고 조치함.
- 팀원 권한: 수락한 팀원은 등록자와 같은 권한을 가짐(서비스 관리·수정·삭제, 팀원 초대·삭제, 등록자 제거).

## 2. 보완 항목

### 2.1 필수 (런칭 전)

**L-01 이용약관 보완**

- 할 일: 아래 항목을 새 버전(`draft-2`)으로 추가함.
  - 권리 침해 게시 중단 요청의 접수·임시조치·재게시 절차(정보통신망법 제44조의2는 조치 내용·절차를 약관에 구체적으로 밝히도록 함, 확인 필요)
  - 사전 감시 의무가 없다는 취지와 신고·요청 접수 후 조치한다는 취지
  - 등록자 책임 범위(등록물로 인해 웹터에 발생한 손해의 부담 등). 책임 주체에 수락한 팀원 포함
  - 팀원의 권한(서비스 삭제·등록자 제거 포함)과 팀원 간 분쟁 시 웹터의 개입 범위
  - 업로드 이미지의 권리·책임·이용 허락 범위(L-07)
  - 운영자 조치(임시 비공개·비공개·삭제·이용 제한) 시 사유 통지와 이의 제기 경로, 조치 기록 보관 사실

  - 시행일, 문의처, 관할

- 영역: 문서, BE, FE (화면이 DB 원문을 표시하려면 원문 조회 API가 필요함. 현재 `GET /api/policies/current`는 원문을 반환하지 않음)

**L-03 권리 침해 접수·임시조치 절차**
- 현재: 신고는 회원만 가능함(정책서 8). 서비스 신고 사유에서 저작권·상표 침해에 해당하는 항목이 `도용·소유권`임. 리뷰·댓글 사유에서 명예훼손에 해당하는 항목이 `욕설·비방`임. 외부 요청은 문의 이메일로만 받음.
- 할 일:
  - 회원·비회원 모두 낼 수 있는 권리 침해 접수 경로 정의(접수 양식 항목, 소명 자료)
  - 임시조치 기간(30일 이내)·통지·재게시 청구 처리 상태 정의
  - 접수·조치 기록 저장 방식 정의
  - 관리자 페이지에서 접수 건을 확인하고 처리하는 화면 정의
- 완료 조건: 접수 → 임시조치 → 신청인·게시자 통지 → 재게시 청구 → 최종 조치 흐름이 문서화되고 구현됨.
- 영역: 정책, BE, FE, 운영
- 선행: 결정 필요(신고 주체 확대 여부, 접수 항목). `reports`에는 비회원 연락처·임시조치 기한 필드가 확인되지 않음.

**L-04 신고 접수 즉시 대응**
- 현재: 런칭 초반 서로 다른 회원 4명 이상 신고 시 자동 임시 비공개함. 4명 도달 전 구간과 1건 단위 요청(권리 침해 요청 포함)의 확인 기준은 정의 필요함. FE 상수(`FE/src/domain/policy.ts`의 `reportThreshold`)는 확정값에 맞춰 반영 필요함.
- 할 일:
  - 관리자 페이지에 처리 대기 신고 건수 표시, 자동 임시 비공개 건 구분 표시
  - 피싱·악성 사유 우선 확인
  - 대기 건수 확인 주기와 처리 기한(내부 기준) 정의
  - 조치는 `moderation_actions`에 기록(처리자·조치 유형·사유·자동 여부)
- 완료 조건: 관리자 페이지에서 대기 건수를 확인하고, 처리 시 상태와 조치 기록이 저장됨.
- 영역: BE, FE(관리자), 운영
- 선행: 결정 필요(확인 주기·기한, 별도 알림 수단 도입 여부)

**L-05 운영 연락처 정식화**
- 현재: 임시 이메일이 푸터·약관 화면·정책서·방침에 쓰임. DB 초안에는 "정식 오픈 전에 기재"로 비어 있음.
- 할 일: 신고·권리 침해·개인정보 문의를 받는 전용 계정 확정 후 일괄 교체함.
- 완료 조건: 모든 노출 위치가 같은 연락처를 표시함.
- 영역: 문서, FE, BE
- 선행: 결정 필요(연락처)

**L-06 서비스 등록 확인 문구 보강**
- 현재: "직접 만들었거나 등록 권한이 있는 서비스이며, 허위 정보·권리 침해·악성 코드·무단 개인정보가 있으면 비공개·삭제될 수 있음에 동의합니다". DB `SERVICE_REGISTRATION` 초안은 별도 문구임. 팀원은 등록 이후 같은 권한을 갖지만 이 확인 문구의 대상이 아님.
- 할 일:
  - 등록물의 적법성 책임이 등록자와 팀원에게 있다는 취지를 문구에 포함하고 화면·DB 문구를 일치시킴
  - 팀원 초대 수락 시 같은 취지의 확인을 받을지 정의
  - 팀원이 등록자를 제거하거나 서비스를 삭제한 경우의 도용·소유권 신고 처리 기준 정의
- 완료 조건: 화면 문구와 `SERVICE_REGISTRATION` 최신 버전이 같고 동의 이력에 버전이 남음.
- 영역: FE, BE
- 선행: 결정 필요(문구, 팀원 수락 시 확인 여부)

**L-07 업로드 이미지 고지·불법 이미지 대응**
- 현재: 업로드는 구현 전이며 파일 선택·미리보기 UI만 있음. 서비스 신고 사유 `부적절 콘텐츠`가 이미지를 포함하는지 정의 필요함. 등록 후 AI 유해성 검사는 방향만 확정되어 세부가 미정임(정책서 8, 10). 비공개 전환 시 이미지 새 요청 제한 방향은 정해져 있음(정책서 4.3, 4.4).
- 할 일:
  - 업로드 화면 고지: 타인의 저작물·초상·개인정보(얼굴, 연락처, 계정 화면 등)와 불법 이미지 업로드 금지, 책임은 업로드한 등록자·팀원에게 있음, 위반 시 비공개·삭제
  - 약관·방침 반영: 이미지 이용 허락 범위(목록·검색·홍보 표시), 보관·삭제, 메타데이터(촬영 위치 등) 처리. 브라우저 자동 압축 과정에서 메타데이터 제거 여부 정의
  - 삭제 대응: 신고·관리자 처리로 비공개·삭제되면 S3 객체 접근 차단·삭제까지 포함, 삭제 후 캐시 반영 시간 정의, 처리 기록 저장
  - 서버(업로드 조건) 측 형식·용량 검증. 브라우저 압축은 서버 검증을 대체하지 않음
  - 이미 내려받거나 외부에 저장된 사본의 회수는 보장하지 않는다는 안내 유지(정책서 4.4)
- 완료 조건: 업로드 화면에 고지가 표시됨. 신고된 이미지를 관리자 페이지에서 비공개·삭제하면 외부 접근이 막히고 조치 기록이 남음.
- 영역: FE, BE, IN(스토리지 설정), 운영
- 선행: 결정 필요(고지 문구, 메타데이터 처리, 삭제 후 반영 시간, 이미지 신고 사유 구분), 확인 필요(불법 이미지 유통 관련 의무 적용 여부)

**L-08 마크다운 무해화·외부 링크 보안**
- 현재: 소개글 마크다운 렌더링 미구현. `이용하기`는 목업(`WtProvider.tsx`의 `launch`).
- 할 일:
  - 마크다운 렌더링 구현 시 HTML 무해화 적용, 링크는 http(s)만, 이미지 문법 비표시(정책서 4.1)

## 3. 게임 서비스 유의점

- 링크만 제공하는 플랫폼이 게임산업법의 등급분류 대상 "제공·유통"에 해당하는지는 자료로 확인되지 않음. 게임물관리위원회 질의 또는 전문가 확인이 필요함.
- 주의 대상: 미등급 게임, 사행성 게임, 청소년 이용불가 게임, 현금화, 확률형 아이템, 랜덤 보상.
- 성인 콘텐츠·도박 서비스는 이미 등록 금지(정책서 1.1).
- 제안(확정 아님):
  - 게임 용도 선택 시 추가 확인 체크 제공(사행성·현금화 없음, 등급분류 필요 여부는 등록자가 확인)
  - 확률형·결제·현금화 요소가 있는 서비스의 등록 제한 또는 표시
- 등급분류 면제 범위는 확인 전에 가정하지 않음.

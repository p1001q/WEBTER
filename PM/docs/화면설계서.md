# WEBTER 화면 설계서 (3차 산출물)

> 최종 HTML(`webter-prototype.html`, `webter-design-system.html`)과 `tokens.json`을 기준으로 작성했다. 작성일 2026-10-22.
> 화면·상태 ID와 주소는 `_build/src/board.js`의 `FRAMES` 목록에서 자동으로 만든 표를 그대로 넣었다(HTML과 어긋나지 않게).
> 기획서·정책서를 다시 복사하지 않고 규칙 ID(R-REPORT · R-IMAGE · R-ACCOUNT · R-REVIEW · R-STATE · R-URL · R-METRIC)와 화면별 적용 차이만 적는다. 규칙 ID의 정의는 제작 프롬프트 13절이다.

## 0. 문서 안내

| 산출물 | 역할 |
|---|---|
| `webter-design-system.html` | 토큰·기본 컴포넌트·상태 예제(18개 절). 프로토타입·보드와 같은 컴포넌트 함수·클래스·토큰을 사용 |
| `webter-prototype.html` | 동작하는 프로토타입(해시 라우팅) + 화면 보드(`#board`) |
| `tokens.json` | 두 HTML의 `:root` CSS 변수와 같은 값(단일 출처 `_build/src/tokens.mjs`에서 함께 생성) |
| `webter-screen-spec.md` | 이 문서 |
| `PROGRESS.md`, `_build/` | 작업 기록, 빌드 소스·점검 스크립트(`node _build/build.mjs`, `node _build/check.mjs`) |

- 용어: 확정 = 문서에서 결정됨 / 제안 = 이번 데모에서 정한 값·표현(확정 아님) / 미정 = 결정하지 않음.
- 모든 서비스·사용자·수치·URL(`example.com` 예약 도메인)은 가상 샘플이다. 인증·접속 검사·AI·서버 저장·외부 이동·클립보드 외 외부 연동은 하지 않는다.

## 2. 화면·상태 목록

하나의 목록(`FRAMES`)을 일반 프로토타입 · 전체 보드 · 그룹 보기 · 단일 보기가 함께 쓴다. 기본 화면과 분기는 같은 ID를 중복 등록하지 않는다.

### 2.1 보드 목록 (69개)

- 표현 단위: **전체 화면**(페이지 문맥·권한·경로가 달라지는 것) / **영역 예제**·**오버레이 예제**(보드 안 컨테이너 크기).
- 권한 열은 보드 프레임이 렌더링한 헤더(비회원=로그인 버튼, 회원=프로필 사진)를 기준으로 했고, 영역·오버레이 예제는 주 사용 권한을 적었다.
- 「프로토타입 재현」은 일반 프로토타입에서 같은 상태를 만드는 주소·조작이다(검증·오류·빈 상태 포함, Tweaks에 모두 중복 등록하지 않음).

### 4.0 공통 셸

- **헤더**: 사이드바 버튼 · 워드마크 · 검색 아이콘 · 서비스 등록 · 로그인(비회원) 또는 프로필 사진(회원) · 오른쪽 끝 오픈소스 입구(`</>`, 이름·툴팁 「오픈소스 영역」, 확장 라벨). 비회원이 「서비스 등록」을 누르면 로그인 안내 모달(R-ACCOUNT 흐름). 로그인·온보딩은 「둘러보기」만 있는 단순 헤더.

- **메인 메뉴**: 홈 | 트렌딩 | 인기 | 최신, 활성 메뉴 밑줄. 로그인·온보딩·등록·수정·완료 화면에서는 숨김.

- **목적·진입**: 서비스 발견의 시작. `#home`, 워드마크.
- **권한**: 비회원 = 기본 구성. 회원이 관심 카테고리를 가졌으면(데모 회원: 놀이·학습) 검색 아래에 「관심 카테고리: 놀이, 학습」 한 줄 + 변경 링크, 트렌딩·인기 섹션에서 해당 카테고리 서비스를 앞에 배치(`01-home--interest`).
- **표시**: 제목 「웹에서 놀다, 웹터.」 · 중앙 검색창(플레이스홀더 「어떤 웹 서비스를 찾고 계신가요?」, 키워드·문장 겸용) · 예시 문장 칩 4개(`01-home--chips`) · 섹션(트렌딩 → 인기 → 최신, 제목 + 더보기 + 카드 그리드). 홈은 항상 카드형(목록형 설정과 무관). 사용 가능한 서비스만 표시.
- **조작**: 검색 제출·예시 칩 → 검색 결과(6절). 카드 → 상세, 더보기 → 해당 목록. 섹션 순서·구성은 `VIEW.homeSections`로 분리(제안, 정책서 12절 미정).
- **빈·오류**: 해당 없음. **모바일**: 2열 변형, 예시 칩은 줄바꿈(`01-home--mobile`).

### 4.2 트렌딩 · 인기 · 최신 (02·03·04) + 공통 필터 (05) — 정책서 5.3·5.5

- **목적·진입**: 집계 기준별 목록. 메인 메뉴, 홈 더보기, 사이드바 카테고리(최신 + 필터).
- **표시**: 제목·설명 · 필터 버튼(적용 개수) · 결과 개수 · 정렬 기준 고정 표시(트렌딩 「최근 3일 점수순」, 최신 「등록일순」)와 인기의 기간 선택(주간/월간/전체, 기본 월간) · 카드형/목록형 토글 · 결과. 트렌딩·인기에 순위 배지(1~3위 버터색). 기간별 순위는 기간별 샘플 활동 자료(`act`)로 계산하며 누적치만으로 계산했다고 주장하지 않는다.
- **서비스 용도 줄**: 목록 제목 아래 가운데에 「전체 | 놀이 생활 학습 | 생산성 디자인·창작 | 유틸리티 개발자 도구 | 기타」(구분선으로 묶음). 여러 개를 고를 수 있고(하나라도 해당하면 포함) 「전체」는 선택을 비움. 필터 패널의 개수에는 포함하지 않음(ⓟ).
- **필터(05)**: 프로젝트 유형 · 기기 지원 · 가격 · 등록 주체 · 지원 언어 · 사용 상태(기본 「사용 가능」만, 「사용 불가능」을 선택해야 노출). 이용 형태 필터는 두지 않음(ⓓ). 모바일 컨테이너(≤560)에서만 「모바일 지원 서비스만 보기」 토글이 보이고 켜진 채 시작, PC에서는 숨김. 결합 방식은 ⓘ.
- **조작 후 동작**: 필터·기간·토글 변경 → 결과와 순서가 즉시 갱신. 「필터 초기화」. 비공개 서비스는 어떤 필터로도 노출되지 않음(R-STATE).
- **빈 상태**: 「조건에 맞는 서비스가 없어요」 + 필터 초기화.
- **관련 정책**: R-STATE(사용 상태 기본값), R-METRIC(인기 점수·기간). **제안 표현**: ⓗ.

### 4.3 검색 결과 (06) — 정책서 5.4

- **표시**: 상단 검색창 유지 · 「‘검색어’ 검색 결과 N개」 · 필터 · 정렬(관련도·인기·최신) · 결과.
- **일반 검색**: 서비스 이름·한 줄 소개·상세 설명·태그에 검색어(공백으로 나눈 모든 단어)가 포함된 서비스. 관련도 = 이름 5·태그 3·한 줄 소개 2·상세 설명 1(데모 규칙).
- **AI 자연어 검색(목업)**: 8자 이상이고 어절 3개 이상이거나 의도 표현이 있으며 미리 정한 의도 규칙(게임·공부·사진/이미지·디자인·여행·PDF·개발)에 맞으면 「AI가 의도를 분석해 찾은 서비스」 박스 + 해석 조건 칩 + 「오늘 남은 AI 검색 2/3회 — 비회원 3회, 회원 20회」 + 추천 이유 한 줄이 붙은 공통 카드. 실제 AI 호출 없음, 같은 입력은 항상 같은 결과. 판별 방식은 **데모 표현 제안**이며 최종 검색 정책·AI 설계가 아니다.
- **소진**: 남은 횟수 0이면 「오늘 AI 검색 횟수를 모두 사용했어요」 + 일반 검색 결과(`#search?q=…&aiLeft=0`로도 재현).
- **결과 없음**: 안내 문구 + 인기 서비스 4개.
- **관련 정책**: 정책서 5.4(AI 후순위·횟수 제한). **영역 예제**: `06-search--chips`.

### 4.4 서비스 상세 (07) — 정책서 4.x·5.1·6.x·7·15

- **진입**: 카드·목록·검색 결과·제작자 프로필·비슷한 서비스·직접 주소(`#detail/<id>`). 비공개 서비스는 일반 사용자에게 접근 제한 안내(`00-shell--restricted`), 소유자에게는 열림(ⓙ).
- **상단 좌측**: 아이콘 · 서비스 용도 칩(복수, 첫 번째가 대표) · 서비스명 · 한 줄 소개. 프로젝트 유형·기기·가격·등록 주체·언어·이용 형태·만든이는 소개 탭으로 옮김(ⓣ).
- **상단 우측 CTA**: 이용하기(가장 강조·새 탭 아이콘) · 좋아요/저장/링크 복사 · GitHub 링크가 있으면 코드 아이콘 하나(툴팁 「소스 보기」, 주요 CTA처럼 강조하지 않음) · 「외부 사이트로 연결되며 해당 서비스의 약관과 개인정보 처리는 제작자 기준입니다.」
- **통계**: 조회수 · 이용하기 클릭 수 · 좋아요 · 저장 · 평가 등급 배지와 추천 비율.
- **분기**: 사용 불가능(`07-detail--unavailable`) = 상단 사유 배너 + 이용하기 비활성, 좋아요·저장 가능, 신규 리뷰는 평가 「미설정」만(R-STATE). 본인 서비스(`07-detail--own`) = 좋아요·저장 비활성 + 안내, 제작자 리뷰·답글 가능, 조회·이용하기 집계 제외(R-REVIEW·R-METRIC).
- **갤러리**: 미리보기 이미지(서비스 단위 16:9 또는 9:16, 꽉 채우기/전체 보이기), 클릭 시 라이트박스 확대, 미리보기가 없으면 영역 생략(`07-detail--gallery`).
- **소개 탭**: 「서비스 정보」(프로젝트 유형·기기 지원·가격·등록 주체(팀명)·지원 언어·이용 형태 6칸) → 「서비스 소개」(마크다운으로 렌더링, **기본 접힘**·상단만 표시, 글이 길 때만 「더보기/접기」 활성, 짧으면 비활성) → 태그(최대 5) · 오른쪽 제작자 카드(사진·이름·아이디·한 줄 소개·프로필 보기, 팔로우 없음).
- **리뷰 탭**: 평가 문구·추천 비율 막대·추천/비추천 개수(미설정·제작자 제외 설명) → 작성 영역(권한별, `07-detail--review-perm`) → 「전체 리뷰 N개 중 M개」 + **추천순(기본)/최신순 토글** → 목록. 각 리뷰: 작성자(닉네임 / 익명 / 비회원 **IP 전체 표시**(ⓢ) / 탈퇴한 사용자 / 제작자), 작성자의 평가(「평가 추천」 등)와 **별개인 리뷰 추천·비추천 버튼**(회원만·본인 리뷰 비활성·1인 1표·바꾸기/취소 가능·서비스 평가 집계에 영향 없음, 비회원은 로그인 안내), 작성일, 내용, 신고, 제작자 답글(들여쓴 박스).
- **댓글 탭(ⓠ)**: 작성 영역(회원만, 비회원은 로그인 안내 / 서비스가 익명 댓글을 허용하면 익명 체크) → 댓글 N개 → 등록순 목록, 모든 회원이 모든 댓글에 **한 단계 답글**(답글에 답글을 달면 같은 줄기에 붙음). 평가·인기 점수·집계와 무관, **추천/비추천 없음**, 링크·개수 제한 없음, 신고 가능(같은 대상 1회), 내 댓글은 수정(모달)·삭제(답글이 있으면 「삭제된 댓글입니다」로 남김), 제작자 댓글에는 「제작자」 표시, 익명은 「익명」(본인에게는 「내 댓글」).
- **리뷰 규칙(R-REVIEW)**: 링크 입력 불가(즉시 오류, 등록 비활성) · 회원 서비스당 1개 · 비회원은 허용 서비스에서만·평가 미설정 고정·IP 기준 서비스당 1개(실제 IP 미수집)·수정 불가·삭제는 관리자만 · 익명은 서비스가 허용할 때만 체크 · 답글은 제작자만, 다른 사용자의 리뷰에 리뷰당 1개(제안), 답글 수정 규칙은 정하지 않음.
- **하단**: 버전 기록(접힘, 버전·제목·내용·일자) · 비슷한 서비스 4개(공개 서비스만).
- **관련 정책**: R-REVIEW · R-STATE · R-METRIC · R-REPORT · R-IMAGE. **모바일**: CTA는 하단 고정 바(좋아요·저장·이용하기).

### 4.5 로그인 (08) — 정책서 2.1

- 구글·카카오 버튼만. 이메일·비밀번호 없음, 네이버·GitHub 안내 없음, 약관 문구 없음(동의는 온보딩).
- 진입: 회원 기능 접근 → 로그인 안내 모달(`08-login--modal`) → 로그인 화면, 또는 「로그인」 버튼.
- 동작(데모): 실제 OAuth 없음. Tweaks가 「회원」 흐름이면 로그인 후 원래 페이지로 복귀, 「신규 가입 흐름」이면 온보딩 후 복귀. 로그인 후 원래 행동은 자동 재실행하지 않음(ⓝ).

### 4.6 온보딩 (09) — 정책서 2.1·15, R-ACCOUNT

- **3단계**: ① 약관 동의 — 필수 3개(이용약관·개인정보 수집·이용·만 14세 이상) + 전체 동의, 모두 동의해야 「다음」 활성(`09-onboarding--consent-unmet`) ② 아이디·닉네임 — 아이디(영문·숫자·마침표·밑줄, 최대 30자, 공백 불가, 중복 불가)와 닉네임(2~20자, 한글 초성·모음 단독·영문·숫자·중간 공백, 앞뒤 공백 불가, 중복 허용) 검증 메시지와 글자 수, 둘 다 통과해야 「다음」(`09-onboarding--id-check`) ③ 관심 카테고리 — 최대 3개, 「건너뛰기」 가능.
- **완료**: 「보던 페이지로 돌아갑니다」 토스트와 함께 원래 페이지로 복귀. 신규 계정은 서비스·저장·리뷰가 없는 상태(빈 상태 확인용). 별도 회원가입 화면·역할 선택 없음.
- **제안**: 아이디 중복 샘플 목록(`TAKEN_HANDLES`), 닉네임 길이 2~20(정책서 제안), 동의 시각·약관 버전 저장은 후속 서버 요구(7절).

### 4.7 서비스 등록 (10) / 수정 (12) — 정책서 4.1~4.9·15

- **진입**: 헤더「서비스 등록」·내 서비스 관리·마이페이지(회원). 비회원은 로그인 안내. 수정은 `#edit/<id>`(본인 서비스만), 같은 폼에 값을 채워 재사용.
- **서비스 소개(마크다운)**: 입력칸에 「작성 / 미리보기」 탭, 지원 문법 안내(`10-register--markdown`). 이미지 문법은 표시하지 않고 설명만 남김, 링크는 http(s)만(클릭 시 외부 이동 데모 안내), 입력은 모두 이스케이프 후 변환.
- **필수**: 서비스 이름 · 한 줄 소개 · 서비스 주소 · 서비스 용도(최대 3, 첫 선택이 대표) · 프로젝트 유형 · 기기 지원 · 가격 · 등록 주체(팀이면 팀명 필수, `10-register--team`). **선택**: 상세 설명 · 이미지 3종 · 태그(최대 5) · GitHub 링크(저장소 주소만) · 지원 언어(기본 한국어).
- **주소 검증(R-URL, 6종)**: 입력 전 / 검사 중 / 접속 가능 / 접속 불가 / 형식·소스 보관 사이트 오류 / 중복 오류. 형식은 클라이언트에서 즉시 검사(https만, github.com 등은 「배포된 주소를 입력하세요」, github.io 허용). 접속 가능·중복은 샘플 규칙(`offline.`·`down.` 호스트는 접속 불가, 등록된 주소는 중복)으로 시연하며 실제 네트워크·서버 검사가 아니다. 주소를 바꾸면 이전 성공 상태를 무효화하고 다시 검사(수정 화면에서 원래 주소로 되돌리면 통과). 입력칸 아래 「데모 입력」 6개 버튼으로 재현(`10-register--url`).
- **이미지(R-IMAGE)**: 아이콘·썸네일·미리보기(최대 8, 16:9/9:16 통일, 꽉 채우기/전체 보이기). 로컬 파일 선택 → 형식(JPG·PNG·WebP)·5MB 검증 → 미리보기 → 삭제. 썸네일은 카드 비율 고정 프레임에서 가운데 기준으로 잘라 표시. 자유 크롭 편집·좌표 저장·서버 업로드는 만들지 않음(크롭 저장 방식은 7절). 미등록이면 대표 카테고리 기본 이미지(`10-register--image`).
- **리뷰·댓글 설정(R-REVIEW)**: 「비회원 리뷰 허용」·「회원 익명 리뷰 허용」·「회원 익명 댓글 허용」 스위치(모두 기본 꺼짐), 켜면 스팸·비방·욕설 주의 안내(`10-register--review-settings`).
- **제출**: 「직접 만들었거나 등록 권한이 있는 서비스이며 … 동의합니다」 체크 필수. 하루 3개 초과 시 안내와 제출 비활성(`10-register--limit`). 임시저장 버튼 없음. 우측 실시간 카드 미리보기 + 필수 항목 진행률(9개 중 n개).
- **오류**: 제출 시 누락 항목마다 인라인 오류, 첫 오류로 스크롤, 「필수 항목을 확인해 주세요」 토스트. 주소 검사 중에는 「검사가 끝난 뒤 다시 시도」.
- **완료(`10-register--done`)**: 「등록한 서비스 상세로 이동 / 내 서비스 관리로 이동」. 수정은 제출 후 내 서비스 관리로 복귀. 결과는 목록·상세·관리·마이페이지에 같은 상태로 반영.

### 4.8 내 서비스 관리 (11) — 정책서 4.3·9

- **표시**: 기업형 대시보드 대신 한 줄 한 서비스. 열 = 서비스(아이콘·이름·한 줄 소개, 비공개 계열이면 배지와 사유) / 사용 상태(선택, 사용 불가능이면 사유) / 통계(조회·이용하기 클릭·좋아요·저장·평가 등급) / 등록일 / 동작(수정·리뷰 확인·버전 기록·삭제). 공개 상태 열은 두지 않는다(R-STATE·M-03).
- **사용 상태**: 「사용 불가능」 선택 → 사유 한 줄 입력 모달(필수, 최대 60자). 확정하면 반영, 취소하면 이전 상태 유지. 「사용 가능」은 즉시 반영.
- **삭제**: 「서비스와 리뷰가 함께 삭제됩니다」 확인 → 완료 시 목록·상세·마이페이지에서 사라짐.
- **버전 기록**: 패널에서 추가·수정·삭제(버전·제목 필수, 일자는 등록 일시 자동·수정해도 유지).
- **빈 상태**: 「아직 등록한 서비스가 없어요」 + 등록하기(`11-manage--empty`). **샘플**: 사용 불가능 `s11`, 임시 비공개 `s17`, 비공개 `s18`(`11-manage--status`).
- **판단 사항**: 비공개 서비스의 수정·삭제·버전 기록·리뷰 확인에는 별도 제한을 두지 않음(ⓙ).

### 4.9 마이페이지 (13) — 정책서 2.3

- 프로필 요약(사진·닉네임·아이디·한 줄 소개) + 내 프로필 보기·서비스 등록. 탭 5개: **내 서비스**(카드 + 사용 불가능·임시 비공개·비공개 상태와 사유, R-STATE) / **저장한 서비스**(공개 서비스만) / **내가 쓴 리뷰**(서비스 링크·평가·수정·삭제) / **내가 쓴 댓글**(서비스 링크·수정 모달·삭제, 익명으로 쓴 댓글 표시, ⓠ) / **계정 설정**(닉네임·아이디·한 줄 소개·외부 링크 5종·관심 카테고리·프로필 사진은 목업, 변경은 세션에만 반영).
- 회원 탈퇴 안내(`13-mypage--withdraw`): 등록 서비스 삭제 · 리뷰는 「탈퇴한 사용자」로 유지 · 좋아요·저장 삭제. 확인해도 실제 계정은 삭제되지 않고 시연 안내 토스트만(R-ACCOUNT).
- 빈 상태: 저장 없음·내 리뷰 없음·내 서비스 없음(`13-mypage--empty`).

### 4.10 제작자 프로필 (14) — 정책서 2.2

- 사진 · 닉네임 · 아이디 · 한 줄 소개 · 외부 링크(블로그·GitHub·Instagram·Velog·포트폴리오, 데모 안내만) · 등록한 서비스 수 · 받은 좋아요 수 · 공개된 서비스 목록 · 프로필 신고(회원, 같은 대상 1회, `14-profile--links`). 팔로우·팔로워·레벨 없음. 비공개 서비스의 내용은 노출하지 않으며, 통계에 포함하는지는 미정(ⓛ).

### 4.11 오픈소스 목록 (15) — 확장 시연 예외

- 입구: 헤더 오른쪽 끝 `</>`(확장 라벨). 화면: 「웹 서비스와 별도 집계」 안내 한 줄 + 트렌딩/인기/최신 탭(`15-opensource--tab`) + 카드(이용하기 대신 「GitHub로 이동」·데모 안내). 일반 웹 목록·순위와 분리, 이용 집계 없이 좋아요×3 + 저장×5(R-METRIC). 등록·상세·운영 흐름 없음.

### 4.12 이용약관 (16) · 개인정보 취급 방침 (17)

- 각 1개 화면: 「초안(임시)」 배지 · 시행일 「정식 오픈 시 기재」 · 법적 검토 전이라는 안내 · 조항 목차(클릭 시 해당 조항으로 이동) · 짧은 샘플 문단(`16-terms--draft`).

## 7. 후속 ERD·DB·API 쟁점

이번에 발견한 미정·충돌·필요 데이터·권한·상태 질문만 적는다. 실제 설계는 하지 않았다.

1. **공개 상태(M-04)**: 공개/비공개/임시 비공개를 MVP 데이터에 포함해야 한다. 관리자(자동 임시 비공개 포함)와 등록자(확장)가 건 비공개의 구분 방식, 사유(`visReason`)와 사용 상태 사유(`reason`)를 별개로 둘지.
2. **탈퇴·리뷰 보존**: 탈퇴 후 리뷰를 「탈퇴한 사용자」로 유지하면서 작성자 연결을 어떻게 끊을지, 익명 리뷰도 본인 수정·삭제를 위해 내부 작성자 식별이 필요함, 서비스 삭제 시 리뷰·버전·반응 연쇄 삭제 범위.
3. **신고**: 대상(서비스·리뷰·답글·프로필)별 중복 판정 키, 서로 다른 회원 수 집계와 임계값(3, 제안), **대상별 숨김·비공개 영향 범위**(리뷰·프로필 신고가 서비스 전체 비공개로 이어지는지 — 문서 불명확), 신고 철회 가능 여부, 사유 보관.
4. **기간 집계**: 최근 3일·주간·월간·전체 점수를 이벤트 로그에서 계산할지 일별 집계로 둘지, 제작자 본인 제외, 이상 징후로 제외된 구간 기록, 오픈소스 별도 집계(좋아요·저장만).
5. **비회원 식별·표시**: IP 해시 저장, 비회원 리뷰에 **IP를 전체 표시**하기로 한 결정(개인정보·법적 검토 필요, 표시 범위·보관 방식), 같은 IP 서비스당 1개 제약, 공용 IP·VPN의 부정확성, 비회원 리뷰 삭제 권한(관리자만).
6. **약관 동의 이력**: 동의 시각·약관 버전 저장(현재는 화면 시연만).
7. **서비스 주소**: 정규화(대소문자·끝 슬래시·`www`), 중복 판정 기준, 접속 검사 결과 저장·재검사 시점, 소스 보관 사이트 목록 관리, GitHub 주소 형식.
8. **이미지**: 크롭 저장 방식(원본+좌표 vs 결과 이미지), 서비스 단위 비율·맞춤 방식 저장, 카드 썸네일 정확한 비율 확정, 카테고리별 기본 이미지 자산.
9. **평가 등급**: 등급을 저장할지 계산할지, 소수점 반올림·구간 경계 확정(ⓕ), 20개 기준, 「많은 리뷰」 구간 적용 여부, 사용 불가능 서비스의 기존 평가 소급 변경 여부.
10. **카테고리**: 복수 선택 최대 개수 확정, 대표 카테고리(선택 순서) 저장, 관심 카테고리 최대 3.
11. **프로필 통계**: 등록한 서비스 수·받은 좋아요에 비공개 서비스를 포함하는지(ⓛ), 탈퇴 사용자 처리.
12. **리뷰·답글**: 답글 수정·삭제 규칙, 리뷰당 답글 1개 확정, 링크 판별 규칙의 서버 측 기준, 제작자 리뷰 1개 제한 여부.
13. **계정**: 아이디 세부 규칙(마침표 연속·시작/끝)·변경 횟수 제한·과거 아이디 예약, 닉네임 길이 확정, 소셜 종류별 별도 계정, 탈퇴 후 재가입.
14. **권한**: 관리자 영역(비회원 리뷰 삭제, 공개 상태 변경, 신고 처리), 비공개 서비스 소유자의 상세·리뷰 확인 권한(ⓙ).
15. **등록 제한**: 하루 3개의 기준 시간대, 삭제해도 개수에 포함되는지.
16. **검색**: 일반 검색 대상(이름·소개·상세 설명·태그)과 인덱스, AI 검색 일일 횟수 저장과 비회원 식별, 의도 해석 결과 저장 여부, 필터 결합 방식(ⓘ) 확정.
17. **집계 이벤트**: 조회·이용하기 클릭(카드·상세 동일 개념), 소스 보기 비집계, 어뷰징 제한(정책서 7) 기록.
18. **댓글(ⓠ)**: 정책서·기획서에 없는 신규 기능. 댓글 테이블(서비스·작성자·부모·익명 여부·삭제 표시), 익명 댓글의 내부 작성자 식별, 비회원 댓글 허용 여부(이번 데모는 회원만 — **제안**), 답글 깊이(한 단계 — 제안), 삭제 시 답글 보존 방식, 댓글 신고 영향 범위, 서비스별 「익명 댓글 허용」 필드, 탈퇴 시 댓글 처리.
19. **리뷰 추천/비추천(ⓡ)**: 리뷰별 반응 저장(회원당 1표, 바꾸기·취소), 어뷰징 방지, 추천순 정렬 기준(추천 수 vs 순추천), 평가 집계·인기 점수에서 제외 명시, 탈퇴 시 처리.
20. **마크다운 소개(ⓤ)**: 서버 측 sanitization 기준, 허용 문법·길이(5000자 제안), 이미지 허용 여부와 저장 방식(이번에는 이미지 미표시), 링크 처리(외부 이동 고지), 접힘 기준(360자·10줄 제안).
21. **사용 상태 vs 공개 상태**: 독립 필드로 두고 사용 불가능 필터가 비공개 서비스를 노출시키지 않도록 하는 규칙.

## 8. 실행·인계·최종 보고

### 8.1 실행 방법·주소

- **여는 방법**: `webter-prototype.html`, `webter-design-system.html`을 브라우저에서 더블클릭. 별도 빌드·설치 불필요, 두 파일은 서로 독립적으로 실행된다(디자인 시스템의 보드 링크는 같은 폴더에 프로토타입이 있을 때만 이동한다).
- **인터넷이 필요한 범위**: 글꼴 2종(Pretendard — jsDelivr, JetBrains Mono — Google Fonts)만. 외부 스크립트·이미지는 없다. 글꼴을 못 불러오면 기본 글꼴로 보이고 `window.__WEBTER_READY__`는 false로 남으며 `window.__WEBTER_ERRORS__`와 화면 왼쪽 아래 오류 박스(「다시 확인」)로 알린다. 완전 오프라인 실행으로 표현하지 않는다.
- **로컬 서버(선택)**: 검수에는 `python3 -m http.server`를 썼지만 사용에는 필요 없다.
- **보드 주소**: 전체 `#board` · 그룹 `#board?group=explore|detail|account|manage|system|mobile` · 단일 `#board?frame=<ID>`(예: `#board?frame=07-detail--unavailable`). `frame`과 `group`이 같이 있으면 `frame` 우선.
- **준비 완료 신호**: `window.__WEBTER_READY__`(초기 false → 선택한 보기의 DOM과 글꼴이 안정되면 true, 보드·그룹·프레임을 바꾸면 다시 판정). 렌더링은 선택한 항목만 하고 가상 스크롤·지연 마운트는 쓰지 않는다.
- **데모 초기화**: 데모 설정 → 「데모 초기화」 또는 새로고침(영속 저장 없음).

### 8.2 기존 자산을 따른 항목과 이유

| 항목 | 이유 |
|---|---|
| `--wt-*` 토큰 이름·기본 9색, 워드마크, Pretendard·JetBrains Mono | 프롬프트 2절: 기존 워드마크·글꼴·스타일 유지 |
| 서비스 카드·썸네일 목업(CSS 구성 가상 스크린샷), 사이드바 구조, 컨테이너 쿼리 반응형 | 최신 규칙과 충돌하지 않는 자산 재사용 |
| 인기·트렌딩 순위 배지, 상세 하단 비슷한 서비스, 등록의 실시간 카드 미리보기·필수 진행률, AI 결과의 추천 이유 한 줄 | 메모지 「프로토타입 단계에서 정한 화면 표현」과 프롬프트 4절 유지 항목 |

### 8.3 문서 충돌과 적용 근거

1.5절 표(ⓐ~ⓞ) 참조.

### 8.4 제안값·확인 필요 정책

- 1.3의 제안값(가중치·횟수·임계값·등록 제한·카테고리 최대·UI 입력 한도), 카드 썸네일 비율 16/10, 홈 섹션 순서.
- ⓕ 비율 반올림, ⓖ 카테고리 진입, ⓗ 고정 정렬 표시, ⓘ 필터 결합, ⓙ 소유자의 비공개 서비스 접근, ⓚ 접근 제한 안내 문구, ⓛ 프로필 좋아요 합산.
- 접근 제한·사유 모달·등록 한도 안내 등 화면 문구는 모두 **화면 제안**이다.
- CSS에 남은 하드코딩 색 6종(`#EEECE6 #E2DFD7 #A5A39D #D5D2CA #3A3A3A #FBFAF7`)은 썸네일 목업·구분선·입력 placeholder·스위치 꺼짐·본문 보조 글자색이며 토큰화하지 않았다. 퍼블리싱 때 토큰으로 승격할지 결정한다.
- 카카오 로그인 버튼 색(`--wt-brand-kakao` 등)은 외부 브랜드 색 제안값이다.

### 8.5 요구사항 대응 결과와 한계

- **대응**: 프롬프트 6절 17개 화면과 공통 오버레이, 8절 필수 인터랙션, 11절 보드(69개 프레임, 그룹 6개, 단일 주소), 9절 디자인 시스템(18개 절), 5·10절 토큰·호환 규칙을 모두 구현했다.
- **디자인 시스템 확인 위치**: 모달 5종·라이트박스·토스트·빈 상태·사이드바·프로필 드롭다운과, 주소 검증 6종·아이디 검증 3종·이미지 오류 상태는 **보드에서만** 보여 주고(중복 복제 금지) 디자인 시스템에는 위치 안내 표를 두었다. 프롬프트 9절이 이 예제들을 디자인 시스템 목록에 적었으므로, 한 곳에 모으길 원하면 해당 보드 프레임을 디자인 시스템으로 옮기면 된다(컴포넌트 함수는 같다).
- **미완료·미검증**: 6.2의 「미검증」 3행(링크 복사 성공 경로, IME·터치·다른 브라우저·실제 기기, html.to.design/Figma 변환). 화면 문구·반응형을 사람 눈으로 전부 확인하지는 않았고 대표 화면 위주로 확인했다.
- **환경 한계**: 파일 생성·브라우저 실행 모두 가능했으나 내장 브라우저가 뷰포트를 축소해 보여 주므로 픽셀 단위 시각 비교는 하지 않았다.

### 8.6 html.to.design 가져오기 전에 확인할 것

1. **글꼴**: 두 글꼴이 로드돼 `__WEBTER_READY__`가 true가 된 뒤 캡처한다(false면 기본 글꼴로 캡처됨).
2. **레이아웃**: 보드의 각 프레임은 너비 고정(1440/390) 컨테이너 안에서 flex/grid+gap으로 구성돼 있고, 전체 보드는 항목이 많아 무거우므로 `#board?group=…` 또는 `#board?frame=…` 단위 캡처를 권장한다. 오버레이 레이어만 absolute를 쓰고 transform·backdrop-filter는 쓰지 않았다.
3. **hover 예제**: 카드·목록·버튼·칩·메뉴의 hover는 `data-hover="true"` 정적 예제로 고정돼 있다(디자인 시스템 `#cards` `#lists` `#buttons` `#controls` `#nav`). 실제 hover 상태에 의존하지 않는다.
4. 가상 요소에는 의존하지 않는다(점·아이콘·구분선은 실제 요소·인라인 SVG, 카드 전체 링크 영역만 `::after`).
5. **변환 검증 여부**: 실제 가져오기는 실행하지 않았고 성공을 보장하지 않는다.

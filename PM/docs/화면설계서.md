# WEBTER 화면 설계서 (현재 구현·요구사항·과거 시안 구분)

> 버전: 1.1 (v1.0: 2026-10-22)
> 최신 동기화: 2026-11-04(v1.1: 팀·이미지·신고·관리자 페이지 결정과 인증 반영).
> 현재 구현 기준은 Next.js `FE/src`이다. 인증은 실제 API로 연결했고 나머지 업무 데이터의 목업과 구분한다. HTML 3종·보드 ID·해시 주소·제작 당시 검수는 과거 시안 기록이다.
> 최신 사용자 결정 > 메모지 확정 > 정책서 > 기획서 > 이 문서·과거 시안 순으로 적용한다. 구현·제안·미정을 자동으로 확정하지 않는다.

## 0. 문서 안내

### 현재 구현과 남은 연동

주요 화면과 목업 상호작용을 구현했다. 기능별 API 구현·프론트 연결을 함께 진행하고 저장 유지·권한·실패 처리를 확인한 후 ERD·API 명세서를 정리한다. 데이터 관계·제약·요청/응답은 기능 개발 전에 맞춘다.

| 영역 | 현재 구현 | 남은 작업·구분 |
|---|---|---|
| 탐색·상세·등록·관리·프로필·마이페이지 | Next.js 화면과 모의 API, 필터·정렬·공통 오류·빈 상태 | 실제 서버 조회·권한·집계·업로드·OG 등. 전체 요구사항·검증 완료를 뜻하지 않음 |
| 서비스 평가 | 글 없는 추천/비추천·리뷰 연결, 리뷰 수정 확인 후 수정 창 | 단독 평가는 로컬 상태. 서버 저장·리뷰와 중복 없는 집계 필요 |
| 리뷰 글 추천/비추천 | 별도 요구사항 유지 | 반응 UI·API, 추천순/최신순 미구현 |
| 알림 | 헤더 미읽음 최신 3건, 전체 화면·필터·읽음/삭제, 목업5종 | 알림9종 확정. 서버 종류/조회/저장·특정 답글 위치 이동·팀 초대 미구현 |
| 이미지 | 파일 선택·미리보기·확대·삭제·자동 맞춤·깨짐 대체 | 1차 연동에서 S3 업로드 구현. 장당 5MB를 넘는 이미지는 브라우저에서 자동 압축(아이콘은 적극적으로, 서비스 화면은 약하게). 직접 편집 미정 |
| 외부 이동 | 이용하기·소스·프로필 링크는 데모 안내 | 실제 새 탭 이동 미연동. 링크 복사는 브라우저 기능 |
| 인증 | 구글 OIDC·서버 세션·가입·계정 설정·로그아웃·탈퇴를 실제 API로 연결해 develop에 반영(PR #29). 서비스·리뷰 등 나머지 데이터는 목업 | 운영 세션·쿠키 전달 세부·로그인 복원 보완·제재·아이디 이력·사진 저장 확인 필요 |
| 오픈소스 독립 영역 | 헤더·라우트·샘플에서 제거 | 런칭 이후 확장 검토. 일반 웹 서비스 GitHub 링크는 유지 |

HTML 파일은 현재 기능의 실행 기준이 아니며 이번에 디자인·모션을 동기화하지 않았다. 2장·6장·8장의 보드·당시 검수/실행 기록은 과거 자료로 유지한다. 구버전 화면과 충돌하면 현재 정책·아래 현행 명세를 따른다.

### 1.4 제안·미정 처리

현재 목업의 화면 수치·문구는 정책 확정을 뜻하지 않는다. 직접 크롭·AI 도입·팀원 범위/시점·저장 폴더·리포트·홍보/광고/의견 창구·보관 정책은 정책서 12장과 메모지를 따른다. 색상·간격·아이콘 크기·정확한 배치·모션은 이번 기능 최신화 대상에서 제외한다.

## 2. 과거 HTML 시안의 화면·상태 목록

하나의 목록(`FRAMES`)을 일반 프로토타입 · 전체 보드 · 그룹 보기 · 단일 보기가 함께 쓴다. 기본 화면과 분기는 같은 ID를 중복 등록하지 않는다.

> 이 장의 화면 ID·해시 주소·크기는 과거 HTML 보드 기록이다. 현행 URL은 4장과 8.0을 따른다.

### 2.1 보드 목록 (69개)

- 표현 단위: **전체 화면**(페이지 문맥·권한·경로가 달라지는 것) / **영역 예제**·**오버레이 예제**(보드 안 컨테이너 크기).
- 권한 열은 보드 프레임이 렌더링한 헤더(비회원=로그인 버튼, 회원=프로필 사진)를 기준으로 했고, 영역·오버레이 예제는 주 사용 권한을 적었다.
- 「프로토타입 재현」은 일반 프로토타입에서 같은 상태를 만드는 주소·조작이다(검증·오류·빈 상태 포함, Tweaks에 모두 중복 등록하지 않음).

- HTML에는 화면 루트(`.wt-app`)와 보드 프레임(`.bd-frame`)에 `data-screen="07-detail"`, 중요 변형에 `data-state="unavailable"`처럼 ID가 붙는다(일반 프로토타입에서는 경로와 현재 상태로 계산: 상세의 `unavailable`·`own`·`review`, 검색의 `ai`·`ai-exhausted`·`empty` 등).

## 4. 화면별 명세

### 4.0 공통 셸·탐색

- 홈·메인 목록·검색·등록·계정 진입을 제공한다. 헤더의 독립 오픈소스 진입은 제거했다.
- 사이드바의 용도 선택은 그 용도 하나를 선택한 트렌딩 목록으로 이동하고 전체는 용도를 해제한다. 트렌딩·인기·최신은 필터를 공유하고 검색은 별도로 관리한다.
- 경로가 바뀌면 공통 모달·사이드바를 닫는다. 뒤로 가기는 앱 내부 복귀를 우선하고 복귀 기록이 없으면 홈으로 보낸다.
- 비회원 회원 기능은 로그인 안내를 제공한다. 등록·수정·관리·마이페이지·알림 등 보호 화면은 AuthGate를 사용하며 서버 권한 검증은 별도다.

### 4.1 홈 — `/`

- 검색과 예시, 트렌딩·인기·최신 미리보기, 관심 용도 우선 표시가 있다. 홈 구성·검색창 역할은 미정 사항을 유지한다.
- 운영 중인 공개 서비스가 없으면 빈 안내와 등록 진입을 제공한다. 비회원 빈 화면의 등록 버튼은 등록 경로의 로그인 게이트를 거쳐 복귀한다.

### 4.2 트렌딩·인기·최신 — `/trending`, `/popular`, `/latest`

- 용도 칩과 공통 필터·보기 전환을 제공한다. 패널의 선택 개수에서는 용도를 제외하고 “용도 제외 초기화”는 용도를 유지한다. 빈 결과의 필터 초기화는 전체를 초기화한다.
- 트렌딩은 최근 3일 점수, 인기는 주/월/전체 기간 점수, 최신은 등록일 최신순이다. 최신은 별도 과거순 정렬을 두지 않고 용도 선택으로 제목을 바꾸지 않는다.
- 공개 탐색은 운영 중만 기본 표시하고 운영 중지는 필터로 포함한다. 모바일은 목록형 기본과 모바일 지원만 보기 토글을 사용한다.

### 4.3 검색 — `/search?q=…`

- 키워드·자연어 모의 검색, 관련도/인기/최신 정렬, 독립 필터·추천 이유·빈 결과를 제공한다.
- AI 실패 시 일반 검색으로 대체하고 재시도한다. 실패한 요청의 횟수는 차감하지 않는 현재 구현 제안이다. 한도 소진 시 일반 검색을 쓴다.
- 로딩은 현재 모의 지연과 연결돼 있으며 실제 조회·횟수 차감은 서버 연동이 필요하다. AI 첫 출시 도입은 미정이다.

### 4.4 서비스 상세 — `/services/[id]`

- 소개 / 리뷰 / 댓글 탭, 제작자 정보와 프로필, 서비스 정보·버전·비슷한 서비스, 이용하기·좋아요·저장·링크 복사·GitHub 소스를 제공한다.
- 없는 서비스·비공개는 안내 본문으로 표시하며 현재 HTTP 200이다. 등록자는 관리 화면에서 비공개 상태·사유를 확인한다. 비공개 서비스와 제작자 본인 조회는 조회수 집계에서 제외한다.
- 이용하기·소스는 실제 외부 이동 대신 데모 안내다. 운영 중지 서비스는 이용하기·단독 평가를 막고 미설정 리뷰·좋아요·저장은 허용한다.
- 단독 추천·비추천은 리뷰 없이 바꾸거나 취소할 수 있다. 리뷰를 작성하면 같은 평가를 공유한다. 리뷰가 있으면 확인창 → 선택 평가를 넣은 수정 창 → 저장 성공 후 변경이며 취소 시 유지한다.
- 리뷰 글 자체 추천·비추천과 추천순/최신순은 별도 요구이며 현재 UI·API 미구현이다. 리뷰와 댓글 수정 시 익명 여부는 바뀌지 않으며 링크를 금지한다.
- 댓글은 현재 회원 작성·500자·한 단계 답글·등록순이다. 답글이 있는 원 댓글 삭제는 자리만 남기고 마지막 답글을 지우면 빈 원 댓글도 제거하는 제안 구현이다.
- 상세 내부에서 탭을 눌렀을 때 URL 동기화는 미적용이다. 외부에서 `?tab=reviews|comments`로 진입하는 동작과 구분한다. 특정 답글 위치 이동은 미구현이다.
- 버전은 현재 목업 고정 날짜·클라이언트 ID를 사용하므로 실제 생성 시각·ID는 연동 때 서버가 처리한다. 이미지별 대체 설명 데이터도 후속이다.

### 4.5 로그인 — `/login`

- develop은 기존 회원·신규 가입 결과를 고르는 구글 로그인 데모다. 복귀 주소는 내부 안전 경로만 허용하며 안내 문구도 같은 검사 결과를 사용한다.
- 인증은 실제 OIDC·서버 세션으로 구현했다. 로그인 복원 보완·만료·쿠키 전달 세부·서버 렌더링과 목업 업무 상태는 분리해서 확인한다.

### 4.6 온보딩 — `/onboarding`

- 필수 동의 → 아이디·닉네임 → 관심 용도(건너뛰기 가능) 순서다. 3단계의 이전은 같은 가입 화면의 입력을 유지한다.
- 중간 입력은 영속 저장하지 않고 이탈 후 다시 시작한다. 약관 페이지를 열었다 돌아오면 체크가 초기화되는 현재 동작도 가입 화면 안의 이전과 구분한다.
- 단계 URL만 바꿔도 필수 동의·아이디/닉네임 검증을 건너뛰어 가입하지 못한다. 이미 로그인한 회원의 재가입은 막는다. 가입 완료 전에는 회원 권한이 없다.
- 아이디·닉네임·14일 2회 변경 제한·구글 사진 미수집은 정책서 2.1을 따른다. 최종 제출 시 가입 트랜잭션과 중복 검증은 서버에서 보장한다.

### 4.7 서비스 등록·수정·완료

- `/services/new`와 `/services/[id]/edit`는 공용 폼이다. URL 형식·중복/접속 검사, GitHub 주소, 필수 항목·태그·이미지·비회원/익명 리뷰·익명 댓글 설정·등록 확인을 제공한다.
- 현재 수정 화면은 등록자만 허용한다. 팀원의 관리·수정·삭제 허용(등록자와 같은 권한)은 아직 미구현이다. `/services/[id]/registered`도 소유자를 검사하며 없는 서비스와 비소유는 같은 안내를 보여 준다.
- 등록/수정 요청부터 성공 후 이동 완료까지 중복 제출을 막고 실패하면 입력·오류 안내를 유지해 재시도한다. URL 변경/이탈 후 늦은 검사 결과는 버린다.
- 이미지 형식·용량·디코드 실패를 검사하고 손상 파일은 저장 대상에서 제외한다. 비동기 연속 추가도 최대 8장을 넘지 않게 한다. 비율·맞춤을 수정한 값도 저장한다.
- 직접 크롭·위치 편집은 없고 자동 맞춤이다. 팀은 팀명만 입력하며 초대·권한 공유·팀원 연결과 AI 일괄 채우기는 미구현이다. 업로드 서버는 1차 연동에서 제외한다.
- 확정 하루 한도는 5개다. 현재 목업 3개 상수는 반영 전이다.

### 4.8 내 서비스 관리 — `/manage`

- 본인 서비스의 운영·공개 상태, 사유, 통계·수정·리뷰·버전·삭제를 제공한다. 비공개도 본인 관리 목록에 남는다.
- 운영 중지 전환은 사유를 입력하며 요청 성공 후 상태·토스트를 갱신한다. 처리 중 모달 잠금·실패 유지 원칙을 적용한다.
- 내 서비스 목록으로 이동하는 링크를 제공한다. 등록 진입은 헤더를 사용한다.

### 4.9 마이페이지 — `/mypage`

상위 탭은 **내 서비스 / 저장한 서비스 / 리뷰·댓글 / 계정 설정** 네 개다. 리뷰·댓글 안에서 내가 쓴 리뷰 / 내가 쓴 댓글 하위 탭을 제공한다. 관심 카테고리·프로필 정보는 계정 설정에서 바꾸고, 저장하지 않고 이탈하면 확인창 없이 변경을 버린다. 구분: 확정

| 목록 | 정렬 | 필터·접근 규칙 |
|---|---|---|
| 내 서비스 | 등록일 최신순(기본) / 과거순 / 전체 기간 인기순. 인기 점수가 같으면 최신순이며 가중치 1·3·5는 제안 | 용도·공통 필터·보기 전환을 제공한다. 운영 중지·비공개·임시 비공개도 기본 포함하며 본인에게 상태와 사유를 표시한다 |
| 저장한 서비스 | **저장 시각** 기준 최신순(기본) / 과거순. 서비스 등록일과 구분한다 | 같은 필터 기능을 제공하되 내 서비스 목록과 필터 상태는 독립적이다. 운영 중지도 기본 포함한다. 비공개 항목은 남기되 이미지·비공개 사유·상세 진입을 제한하고 저장 해제만 허용한다 |

- 두 목록에는 모바일 지원 서비스만 보기 토글을 두지 않는다. 운영 상태는 필터로 좁힐 수 있다.
- 비공개 저장 항목에는 접근 불가 안내를 표시하며, 저장 탭·헤더·사이드바의 개수는 비공개를 포함한 같은 기준으로 센다. 카드형·목록형 모두 이 규칙을 적용한다.
- 내 서비스 목록과 관리 화면 사이에 이동 링크를 제공한다. 계정 설정에는 로그아웃도 제공한다.
- 마이페이지 리뷰·댓글은 현재 별도 정렬 없이 유지한다. 서비스 상세의 리뷰 추천순·최신순 요구사항과 구분한다.
- 저장 폴더·활동 리포트 탭은 도입 미정이며 현재 제공하지 않는다.

현재 URL `tab=services|saved|reviews|comments|settings`에서 comments는 리뷰·댓글 상위 탭의 하위 상태다. 저장 목록 API에는 저장 시각이 필요하며 목업 Set 순서를 실제 데이터 계약으로 쓰지 않는다. 프로필 사진 선택은 늦은 파일 읽기가 새 선택·되돌리기·기본 사진을 덮어쓰지 않게 처리한다.

### 4.10 제작자 프로필 — `/users/[id]`

- 공개된 서비스·등록 개수·받은 좋아요, 닉네임·아이디·소개·프로필 사진·외부 링크·신고를 제공한다. 없는 회원·객체 상속 속성 이름은 회원으로 처리하지 않는다.
- 비공개 내용은 노출하지 않으며 통계에 포함하는지는 미정이다. 본인 프로필은 계정 설정으로 이동한다. 팀원 참여 프로젝트는 후속 요구다.

### 4.11 오픈소스 독립 목록 — 현행 진입 없음

현재 라우트·헤더·샘플에서 제거했다. 런칭 이후 확장으로 재검토하며 일반 웹 서비스의 GitHub 소스 링크는 유지한다. 2장의 오픈소스 보드는 과거 시안이다.

### 4.12 약관·개인정보 — `/terms`, `/privacy`

현재 초안·법적 검토 전 상태로 표시한다. 서버 약관 버전과 동의 이력을 연결해야 하며 기존 동의가 가리키는 문구를 덮어쓰지 않는다.

### 4.13 공통 오류·오버레이·로딩

- API 실패는 연결·서버·로그인 만료·권한·대상 없음·규칙 위반으로 구분한다. 쓰기 실패는 입력·모달을 유지하고 등록/수정은 제출 위치에도 안내한다. 성공 여부 반환 후 닫는 구조다.
- 삭제·신고·운영 중지·탈퇴 등 처리 중 Esc·배경·닫기를 잠그고, 늦게 끝난 요청이 다른 모달을 닫지 않도록 현재 모달을 비교한다. 신고 취소 등 모든 경로의 잠금은 실제 연동 검수에서 재확인한다.
- 만료 모달을 닫으면 현재 입력을 복사할 수 있도록 남긴다. 재로그인하면 작성 내용은 보존하지 않는다. 만료 즉시 회원 상태 초기화는 기존에 보류했고 실제 인증 연결과 재검토한다.
- 오프라인 초기 상태·연결 복귀를 표시하고 조회/클릭 집계 실패는 일반 오류 토스트로 알리지 않는다. 실패한 집계 뒤 이전 객체를 덮어쓰지 않는다.
- 깨진 이미지 대체, 데이터 없음, 본문 오류 경계와 앱 전체 오류, 목록/상세/마이페이지 스켈레톤이 있다. 리뷰·댓글 스켈레톤은 준비됐으나 실제 로딩 연결이 필요하다. M-44의 처리 방식은 구현 제안이다.

### 4.14 알림 — `/notifications`

- 회원 헤더는 미읽음 최신 3건과 더보기를 제공한다. 목록은 전체/미읽음·개별/전체 읽음·삭제를 제공한다.
- 현재 목업5종과 로컬 상태이며 확정된9종과 다르다. 서비스 리뷰/댓글 탭까지만 이동한다. 서버 누적 조회·보관·실제 대상 권한 확인·특정 답글 위치 이동·초대 수락은 후속이다.
- 내 서비스 리뷰/댓글·내 댓글 답글·내 리뷰 제작자 답글·임시 비공개가 목업 종류다. 추가 확정 종류는 임시 비공개 해제·최종 비공개·내 작성 대상 임시 비공개·서비스 등록 제한이다. 팀 초대는 별도이고 좋아요·저장·리뷰 투표 알림은 제외한다. 표현·보관은 미정이다.

### 4.15 팀원 초대·참여 프로젝트

- 고정 조직형 팀은 만들지 않고 서비스마다 공개 아이디로 회원을 검색해 초대한다. 수신자가 수락한 뒤 팀원이 된다. 등록자를 제외하고 서비스당 최대 5명이다.
- 수락한 팀원은 등록자와 같은 권한(서비스 관리·수정·삭제, 버전 기록 수정, 팀원 초대·삭제, 등록자 제거)을 가진다. 서비스 상세의 팀원, 팀원의 마이페이지·프로필의 본인 서비스로 연결한다. 기존 등록자 전용 관리·수정 규칙을 대체한다.
- 이전 서비스의 팀원 불러오기는 두지 않고 최근 검색한 아이디를 다시 고르는 흐름을 제공한다.
- 등록자가 탈퇴해도 팀원이 남은 서비스는 삭제하지 않는다. 탈퇴한 회원은 팀원 관계에서 빠지고 가장 먼저 수락한 팀원이 등록자 자리를 잇는다. 팀원도 제작자로 취급해 자기 서비스 좋아요·저장·단독 평가는 등록자와 똑같이 막고 제작자 답글은 팀원도 쓴다.
- 초대는 받은 사람이 거절해도 알림을 지우지 않고 "거절함"으로 표시하며(수락은 "수락함"), 보낸 사람이 대기 중인 초대를 취소하면 초대와 알림을 함께 삭제한다. 재초대는 제한하지 않는다. 초대 만료·역할 표시는 확장이다.
- 구글 로그인·회원 기능·알림 이후 착수한다. 현재는 팀명만 입력하고 공유 권한·초대/수락 UI·업무 API는 미구현이다. 수락 초대만 연결하는 현행 DB 제약과 별개로 권한 적용을 구현해야 한다.
- 회원 고유 번호로 관계를 유지하고 수신자만 초대를 수락한다. 팀원 관리 권한을 비공개 이미지·대상의 무제한 공개로 해석하지 않으며 대상별 서버 권한을 검증한다. 팀원 서비스의 프로필 표시는 일반 서비스와 같은 공개 규칙을 따른다(타인에게는 공개 서비스만, 본인에게는 비공개 포함).

### 4.16 관리자 페이지 — `/admin` (MVP 포함, 미구현)

- 관리자 권한을 가진 회원만 같은 구글 로그인으로 접근한다. 관리자 지정은 개발자가 DB에서 직접 하며 서버가 권한을 검증한다.
- 신고 목록·상세: 대상 미리보기·사유·신고 건수를 보여 주고 처리 대기 건수를 표시한다.
- 처리: 복구·최종 비공개·삭제·기각을 선택하며 조치 사유와 이력이 자동으로 남는다. 복구하면 그 대상의 열린 신고를 기각 처리한다.
- 임시 비공개 목록, 회원 제재 지정(경고·서비스 등록 제한·계정 이용 제한)과 사유 알림, 조치 이력 조회를 제공한다.
- 통계 대시보드·공지·일괄 처리는 확장이다. 현재 화면은 없으며 상세 화면 구성은 구현 전에 정한다.

## 7. 후속 ERD·DB·API 쟁점

1. **개발 순서:** API와 프론트 연동을 기능별로 함께 진행하고 결과에서 ERD·API 명세서를 정리한다. 기존 설계는 참고 검토본이며 관계·제약·요청/응답은 기능 구현 전에 맞춘다.
2. **조회 분리:** 전체 snapshot·사용자/리뷰 배열을 실제 API로 그대로 만들지 않고 공개 목록·상세·본인 데이터를 나눈다. 필터·정렬·페이지네이션과 탈퇴 응답의 재조회 범위를 맞춘다. 목록 응답은 서비스 목록·검색·마이페이지 목록이 페이지 번호(offset), 알림·댓글·리뷰가 마지막 항목 기준(cursor, 더보기·무한 스크롤) 방식이다.
3. **서비스 평가·리뷰·리뷰 글 투표:** 한 회원·서비스의 단독 평가와 리뷰 평가는 중복 없이 공유한다. 리뷰 글 투표는 별도다. 단독 평가의 리뷰 숫자·리뷰 삭제 후 유지·DB 관계는 미정 또는 설계 과제다.
4. **집계 갱신:** 서버 전체 집계에 현재 리뷰 목록을 다시 더하지 않는다. 조회·좋아요·저장 응답 역전이 최신 서비스 값을 덮어쓰지 않도록 부분 갱신·버전·재조회 방식을 맞춘다.
5. **익명·권한:** 공개 응답에서 익명 회원 ID·비공개 사유·이미지를 제외하고 본인 여부·허용 동작을 전달한다. 비회원 IP 중복·보관·IPv6·HMAC 키 정책은 여전히 필요하다.
6. **최신 확정값:** 신고 런칭 초반 4명·하루 등록 5개·아이디 변경 14일 2회를 서버에 적용한다. 목업 3명·3개와 구분하고 아이디 변경 이력을 저장한다. 인기 가중치·AI 한도는 제안이다.
7. **저장 목록:** 저장 시각 최신/과거순과 안정적인 동률 처리가 필요하다. 본인/저장 목록은 운영 중지도 기본 포함한다. 비공개 해제·개수·이미지/사유 제한을 함께 처리한다.
8. **인증:** OIDC·세션·CSRF·가입 대기/최종 저장은 구현해 develop에 반영했다. 운영 기간·쿠키 전달 세부·서버 로그인 복원·만료·제재·사진 서버 저장은 후속이다. 인증 연결과 업무 데이터 목업을 구분한다.
9. **이미지·외부 이동:** 1차 연동에서 이미지 업로드를 S3(비공개 버킷·CloudFront·직접 업로드)로 구현하고 큰 이미지는 브라우저에서 압축한다. 파일 선택과 ID/URL 저장은 업로드와 분리해 연결한다. 비공개 이미지 새 요청·캐시·임시 URL 정책이 필요하다. 이용하기·소스·프로필 링크의 실제 이동, 서버 생성 ID/시각·OG·대상 없음의 HTTP 응답도 연결한다.
10. **신고·댓글·탈퇴:** 최신 탈퇴 규칙과 DB FK, 운영 기록 보존을 대조한다. 댓글 답글 깊이·삭제 자리 등 제안, 프로필 신고는 프로필만 숨기는 것으로 정했고 운영 보관·주소/유해성 검사는 미정이다.
11. **알림·팀원:** 서버 누적 조회·읽음/삭제·대상 식별자·특정 답글 이동·수신자 권한을 구현한다. 수락 초대만 팀원 연결 제약(V3)이 있고 현재 초대/연결·공유 권한 화면은 없다. 팀원은 등록자 제외5명이며 등록자와 같은 권한(서비스 삭제·등록자 제거 포함)을 가진다. 팀원이 남은 서비스는 등록자 탈퇴 시 유지하고 먼저 수락한 팀원이 잇는다. 초대는 거절함/수락함 표시, 취소 시 초대와 알림 삭제다. 초대 수락 flush 후 팀원 저장 순서를 확인한다.
12. **계약·회귀 확인:** enum은 DB 코드값을 프론트 어댑터로 변환하고 HTTP 오류를 ApiError로 매핑한다. 지연·실패·연속 입력·중복 제출·모달 잠금·저장 유지·권한을 기능별로 확인한다. 전면 스토어 분해·라이브러리 교체는 선행 조건이 아니다.

### 8.1 실행 방법·주소

- **여는 방법**: `프로토타입.html`, `디자인시스템.html`을 브라우저에서 더블클릭. 별도 빌드·설치 불필요, 두 파일은 서로 독립적으로 실행된다(디자인 시스템의 보드 링크는 같은 폴더에 프로토타입이 있을 때만 이동한다).

- **로컬 서버(선택)**: 검수에는 `python3 -m http.server`를 썼지만 사용에는 필요 없다.
- **보드 주소**: 전체 `#board` · 그룹 `#board?group=explore|detail|account|manage|system|mobile` · 단일 `#board?frame=<ID>`(예: `#board?frame=07-detail--unavailable`). `frame`과 `group`이 같이 있으면 `frame` 우선.
- **준비 완료 신호**: `window.__WEBTER_READY__`(초기 false → 선택한 보기의 DOM과 글꼴이 안정되면 true, 보드·그룹·프레임을 바꾸면 다시 판정). 렌더링은 선택한 항목만 하고 가상 스크롤·지연 마운트는 쓰지 않는다.
- **데모 초기화**: 데모 설정 → 「데모 초기화」 또는 새로고침(영속 저장 없음).

- 접근 제한·사유 모달·등록 한도 안내 등 화면 문구는 모두 **화면 제안**이다.
- CSS에 남은 하드코딩 색 6종(`#EEECE6 #E2DFD7 #A5A39D #D5D2CA #3A3A3A #FBFAF7`)은 썸네일 목업·구분선·입력 placeholder·스위치 꺼짐·본문 보조 글자색이며 토큰화하지 않았다. 퍼블리싱 때 토큰으로 승격할지 결정한다.
- 카카오 로그인 버튼 색(`--wt-brand-kakao` 등)은 기존 HTML 자산에 남은 값이며 구글 단일 로그인인 첫 출시에는 적용하지 않는다.

### 8.5 제작 당시 요구사항 대응 결과와 한계

아래 완료·미검증 표기는 당시 시안에 대한 기록이다. 현재 첫 출시 범위와 인증·서버·배포의 완료 여부는 별도로 확인한다.

- **대응**: 프롬프트 6절 17개 화면과 공통 오버레이, 8절 필수 인터랙션, 11절 보드(69개 프레임, 그룹 6개, 단일 주소), 9절 디자인 시스템(18개 절), 5·10절 토큰·호환 규칙을 모두 구현했다.
- **디자인 시스템 확인 위치**: 모달 5종·라이트박스·토스트·빈 상태·사이드바·프로필 드롭다운과, 주소 검증 6종·아이디 검증 3종·이미지 오류 상태는 **보드에서만** 보여 주고(중복 복제 금지) 디자인 시스템에는 위치 안내 표를 두었다. 프롬프트 9절이 이 예제들을 디자인 시스템 목록에 적었으므로, 한 곳에 모으길 원하면 해당 보드 프레임을 디자인 시스템으로 옮기면 된다(컴포넌트 함수는 같다).
- **미완료·미검증**: 6.2의 「미검증」 3행(링크 복사 성공 경로, IME·터치·다른 브라우저·실제 기기, html.to.design/Figma 변환). 화면 문구·반응형을 사람 눈으로 전부 확인하지는 않았고 대표 화면 위주로 확인했다.
- **환경 한계**: 파일 생성·브라우저 실행 모두 가능했으나 내장 브라우저가 뷰포트를 축소해 보여 주므로 픽셀 단위 시각 비교는 하지 않았다.

### 8.6 html.to.design 가져오기 전에 확인할 것

1. **글꼴**: 두 글꼴이 로드돼 `__WEBTER_READY__`가 true가 된 뒤 캡처한다(false면 기본 글꼴로 캡처됨).
2. **레이아웃**: 보드의 각 프레임은 너비 고정(1440/390) 컨테이너 안에서 flex/grid+gap으로 구성돼 있고, 전체 보드는 항목이 많아 무거우므로 `#board?group=…` 또는 `#board?frame=…` 단위 캡처를 권장한다. 오버레이 레이어만 absolute를 쓰고 transform·backdrop-filter는 쓰지 않았다.
3. **hover 예제**: 카드·목록·버튼·칩·메뉴의 hover는 `data-hover="true"` 정적 예제로 고정돼 있다(디자인 시스템 `#cards` `#lists` `#buttons` `#controls` `#nav`). 실제 hover 상태에 의존하지 않는다.
4. 가상 요소에는 의존하지 않는다(점·아이콘·구분선은 실제 요소·인라인 SVG, 카드 전체 링크 영역만 `::after`).
5. **변환 검증 여부**: 실제 가져오기는 실행하지 않았고 성공을 보장하지 않는다.

- 현재 파일명을 고정 이름으로 맞추고, 현재 레포에 없는 제작 당시 빌드·토큰 자료는 과거 자료로 구분했다.

## 1. 서비스 범위

| 항목 | 정책 | 구분 |
|---|---|---|
| 등록 대상 | 웹 서비스. 설치형 앱만 있고 웹으로 체험할 수 없는 서비스는 제외한다. 웹 데모가 있는 앱 프로젝트는 등록할 수 있다. GitHub 링크만 있는 서비스(오픈소스)는 MVP에서 받지 않고 확장에서 별도 영역으로 받는다(4.10) | 확정 |
| 등록 조건 | 배포되어 지금 바로 이용할 수 있는 서비스만 등록한다. 배포 전·출시 예정 서비스는 받지 않는다 | 확정 |
| 실행 방식 (MVP) | 서비스 링크(웹 실행 주소)를 등록받는다. 소스를 공개한 서비스는 GitHub 링크도 함께 받는다. 서비스 링크는 `이용하기`를 누르면 새 탭에서 연다. GitHub 링크는 상세 페이지에 코드 아이콘(`</>`)으로만 연결한다. iframe 실행과 직접 호스팅은 하지 않는다 | 확정 |
| 내부 연결 | 사이트 안에서 바로 실행하는 방식은 확장 1순위이며, 멘토 의견을 들은 뒤 MVP 포함 여부를 결정한다 | 확정 |
| GitHub 링크 | 소스를 공개한 서비스는 GitHub 저장소 링크를 별도 항목(선택)으로 입력받아 상세 페이지에 코드 아이콘(`</>`)으로 연결한다. 서비스 링크 칸에는 GitHub 저장소 주소를 넣을 수 없다. GitHub 링크만 있고 서비스 링크가 없는 서비스(오픈소스)는 확장에서 별도 영역으로 받는다(4.10) | 확정 |
| 주소 검증 | `https` 주소만 받는다. `github.com` 같은 소스 보관 사이트의 주소는 거절하고 "배포된 주소를 입력하세요"라고 안내한다(`github.io`는 허용). 등록 시 서비스 링크의 접속 가능 여부를 자동 검사한다. GitHub 주소는 GitHub 링크 칸에 입력하도록 함께 안내하며, GitHub 링크 칸은 GitHub 저장소 주소만 받는다 | 확정 |
| 주소 변경 | 서비스 주소는 수정할 수 있다. 변경할 때마다 위 검증과 접속 검사를 다시 실행한다. 주기적 자동 점검은 확장 | 확정 |
| 주소 중복 | 같은 주소는 중복 등록할 수 없다 | 확정 |
| 측정 가능한 행동 | 서비스 상세 조회와 `이용하기` 클릭까지다. 외부 서비스 내부의 사용 시간과 행동은 알 수 없다 | 확정 |

### 1.1 등록 금지 서비스

다음 서비스는 등록할 수 없고, 발견되면 숨김·삭제 대상이다.

- 피싱·악성 사이트
- 불법·사기·도박 서비스
- 성인 콘텐츠 서비스 (MVP에서는 받지 않는다)
- 타인의 저작권·상표를 침해하는 서비스, 이미지, 소개

- 같은 주소의 중복 등록을 막는다.
- 신고 사유에 "도용·소유권"을 둔다.

## 2. 회원·계정

### 2.1 계정과 가입

| 항목 | 정책 | 구분 |
|---|---|---|
| 회원 체계 | 이용자와 제작자를 구분하지 않는 단일 회원 체계 | 확정 |
| 로그인 방식 | **소셜 로그인만** 제공한다. MVP는 구글과 카카오, 시간이 되면 네이버와 GitHub를 추가한다. 자체 이메일·비밀번호 로그인은 두지 않는다. 멘토에게 보안과 적절성을 확인한다 | 확정 (멘토 확인 필요) |
| 인증 구성 | 로그인은 **Supabase Auth 중심**으로 처리한다. 별도 Spring Boot 서버가 반드시 있다는 전제로 설계하지 않는다. 구글·카카오 소셜 로그인은 기존 정책을 유지한다. 이메일·소셜 식별자·세션·토큰은 Auth 관리 영역에 두고 앱 테이블에 중복 저장하지 않는다(제안) | 확정(Auth 채택), 제안(저장 구조) |
| 소셜 계정 중복 | 소셜 로그인 종류마다 별도 계정으로 처리한다. 계정 연동은 확장. **다만 Supabase Auth의 동일 이메일 identity 자동 연결 동작과 충돌하므로 계정 분리 정책을 유지할지는 사용자 확인이 필요하다** | 확정, 충돌 해소 미정 |
| 가입 흐름 | 비회원으로 둘러보다가 회원 기능(리뷰 평가, 좋아요, 저장, 서비스 등록, 신고 등)을 누르면 로그인 안내 후 로그인 화면으로 이동한다. 소셜 로그인(신규는 회원가입) → 온보딩(약관 동의, 아이디·닉네임 설정, 관심 카테고리 선택은 건너뛰기 가능) → 사용자가 보던 페이지로 되돌려 보낸다 | 확정 |
| 약관 동의와 연령 | 온보딩에서 이용약관과 개인정보 수집·이용에 동의받는다. 만 14세 미만의 가입은 제한한다. 이용약관과 개인정보처리방침은 필요한 항목만 갖춘 초안으로 두고 나중에 보완한다. 법적 요건은 구현 전에 확인한다 | 확정(방식), 법적 요건 확인 필요 |
| 계정 정보 | 회원 고유 번호(시스템이 부여, 변경 불가, `auth.users.id`의 UUID를 참조 — 제안), 아이디, 닉네임, 프로필 사진, 이메일(소셜 계정에서 받으며 비공개) | 확정(아이디·닉네임), 제안(사진·이메일) |
| 아이디 | 중복 불가인 공개 식별자. 허용 문자와 길이는 인스타그램 아이디 규칙을 참고한다(영문·숫자·마침표·밑줄, 최대 30자, 공백 불가). 세부 규칙은 구현 때 확인한다. 변경할 수 있다. 서비스 내부에서는 변경되지 않는 회원 고유 번호로 회원을 식별하므로, 아이디를 바꿔도 공동 작업자 등의 연결이 유지된다. 변경 횟수 제한은 미정 | 확정(변경 가능), 미정(횟수 제한) |
| 닉네임 | 중복 허용, 변경 가능. 2~20자. 한글(초성·모음 단독 포함), 영문, 숫자, 중간 공백을 허용하고 앞뒤 공백은 허용하지 않는다. 욕설 필터는 두지 않는다 | 확정(중복·변경·욕설 필터 없음·앞뒤 공백·초성), 제안(길이) |
| 관심 카테고리 | 최대 3개. 가입 직후 선택하거나 건너뛸 수 있고, 마이페이지에서 변경한다 | 확정 |
| 회원 탈퇴 | 등록한 서비스는 삭제한다. 작성한 리뷰는 "탈퇴한 사용자"로 표시하고 유지한다. 좋아요와 저장은 삭제한다 | 확정 |
| 관리자 지정 | 가입 화면 없이 개발자가 DB에서 직접 지정한다(소수) | 확정 |

## 4. 서비스 등록·관리

### 4.1 등록 항목

| 항목 | 필수 | 규칙 |
|---|---|---|
| 서비스 이름 | 필수 | |
| 한 줄 소개 | 필수 | |
| 서비스 주소 | 필수 | 서비스 링크: 웹에서 바로 이용할 수 있는 실행 주소 (1번 항목의 검증 적용) |
| 서비스 용도 | 필수 | 복수 선택 가능(최대 3개). 첫 번째로 고른 카테고리가 대표 카테고리. 목록은 4.8 참고 |
| 프로젝트 유형 | 필수 | 토이 / 사이드 / 정식 서비스 |
| 기기 지원 | 필수 | PC, 모바일 복수 선택 |
| 가격 | 필수 | 무료 / 유료 / 일부 유료 |
| 등록 주체 | 필수 | 개인 / 팀(팀이면 팀명 입력) |
| 상세 설명(서비스 소개) | 선택 | 마크다운으로 작성하고 상세 페이지에서 꾸며서 보여 준다. 등록·수정 화면에 작성/미리보기를 둔다. 최대 길이 5000자, 이미지 문법은 표시하지 않음, 링크는 http(s)만(제안) |
| 이미지(아이콘, 썸네일, 미리보기) | 선택 | 4.4 참고 |
| 태그 | 선택 | 자유 입력 최대 5개. 소분류 역할을 하며 검색의 보조 데이터로 사용. 태그 추천은 확장(4.8) |

필수 항목의 구성은 제안이며, 이미지가 필수가 아니라는 점과 태그 최대 5개는 확정이다. 그 밖에 GitHub 링크(소스를 공개한 서비스의 저장소 주소, 선택)와 지원 언어(한국어/영어 복수 선택, 기본값 한국어)를 입력받는다(4.9). 등록을 제출하려면 "직접 만들었거나 등록 권한이 있는 서비스이며, 허위 정보·권리 침해·악성 코드·무단 개인정보가 있으면 비공개·삭제될 수 있음에 동의합니다"에 체크해야 한다(15번). 등록한 서비스는 등록자가 수정할 수 있다.

### 4.3 서비스 상태

서비스에는 두 종류의 상태가 있다.

| 상태 | 값 | 변경 주체 | 규칙 | 구분 |
|---|---|---|---|---|
| 사용 상태 | 사용 가능 / 사용 불가능 | 등록자 | 사용 불가능이면 사유를 한 줄로 입력하고 서비스 상단에 표시한다. 종료·정지·점검 같은 구분은 사유로 표현한다. `이용하기`는 비활성화한다. 기본 목록에서는 숨기고, 필터에서 "사용 불가능"을 선택하면 볼 수 있다. 필터 기본값은 "사용 가능"만 선택. 사용 불가능 상태에서도 좋아요·저장은 가능하고, 리뷰는 추천·비추천 없이(미설정) 쓸 수 있다 | 확정 |
| 공개 상태 | 공개 / 비공개(임시 비공개 포함) | 관리자, 자동 임시 비공개 | 등록 즉시 공개한다. 「공개」일 때는 어떤 화면에도 표시하지 않는다. 「비공개」(임시 비공개 포함)일 때만 비공개 상태임과 사유를 표시하며, 표시되는 곳은 등록자의 내 서비스 관리와 마이페이지다. 일반 사용자는 비공개 서비스를 목록·검색·상세 어디에서도 볼 수 없다. 등록자는 상태를 바꿀 수 없다 | 확정 |

배포 전·출시 예정 상태는 두지 않는다.

등록자가 자기 서비스를 직접 비공개로 바꾸고 다시 공개로 되돌리는 기능은 **확장**이다(11). 관리자가 건 비공개와 등록자가 건 비공개는 구분해야 하며 구분 방식은 확장 때 정한다. 공개 상태 필드는 DB 설계에 MVP부터 포함한다. 구분: 확정

### 4.4 이미지

| 종류 | 용도 | 규칙 |
|---|---|---|
| 아이콘 | 목록형 보기, 이후 다른 화면에서도 사용 가능 | 정사각형, 512×512 이상 권장 |
| 썸네일 | 카드형 보기 | 카드 비율로 잘라서 등록 |
| 미리보기 | 상세 페이지 | 최대 8장. 서비스 단위로 가로 16:9 또는 세로 9:16 중 하나를 선택하고 모든 이미지를 같은 비율로 통일한다. 이미지 맞춤은 "꽉 채우기"(등록자가 크기와 위치를 조정해 자르기) 또는 "전체 보이기"(비율 유지, 남는 곳은 여백) 중 선택 |

- 세 이미지 모두 선택 입력이다. 아이콘과 썸네일을 올리지 않으면 선택한 서비스 용도별 기본 이미지를 보여 주고, 미리보기를 올리지 않으면 해당 영역은 생략한다. 정확한 카드 비율은 화면 디자인에서 정한다.
- 업로드 형식은 JPG, PNG, WebP이고 장당 5MB 이하이다. 부적절한 이미지는 서비스 신고로 처리한다. 구분: 확정

### 4.5 버전 기록

서비스별로 업데이트 이력을 남길 수 있다. 등록자가 버전, 제목, 내용을 입력하고 일자는 등록 일시가 자동으로 입력된다. 등록자가 수정·삭제할 수 있고, 최초 등록 일시는 유지한다. 상세 페이지에서는 눈에 띄지 않게 하단에 두며 앱스토어처럼 존재만 하게 한다. 구분: 확정

### 4.6 삭제

서비스를 삭제하면 서비스와 리뷰가 함께 삭제된다.

### 4.7 등록 개수 제한

한 계정은 하루에 서비스를 3개까지 등록할 수 있다(초기값). 총 등록 개수는 제한하지 않는다. 구분: 확정(방식), 제안(수치)

### 4.8 서비스 용도 카테고리와 태그

서비스 용도는 "무엇을 하려고 들어가는가"라는 사용 목적을 기준으로 나눈다. 기술(AI 등), 형태, 가격은 카테고리에 섞지 않는다. 카테고리는 한 단계만 두고, 세부 분류는 태그가 맡는다.

| # | 카테고리 | 예시 |
|---|---|---|
| 1 | 놀이 | 웹게임, 퍼즐, 퀴즈, 룰렛, 심리테스트 |
| 2 | 생활 | 여행, 음식, 지도, 돈 관리 |
| 3 | 학습 | 단어장, 공부 도구, 학습 게임 |
| 4 | 생산성 | 할 일, 타이머, 문서·일정 |
| 5 | 디자인·창작 | 이미지 편집, 색상, 그림, 음악 |
| 6 | 유틸리티 | 변환·계산·파일 같은 작은 도구 |
| 7 | 개발자 도구 | API 테스트, 코드 도구 |
| 8 | 기타 | 위에 맞지 않는 서비스 |

- 홈, 목록 위 카테고리 줄, 사이드바, 등록 화면에는 위 순서로 표시한다.
- 서비스는 카테고리를 복수로 선택할 수 있다(최대 3개는 제안). 첫 번째로 고른 카테고리가 대표 카테고리이며 기본 이미지에 쓴다. 필터와 관심 카테고리는 선택한 카테고리 중 하나라도 해당하면 서비스를 보여 준다.
- 소분류는 두지 않고 태그(자유 입력, 최대 5개)가 그 역할을 한다.
- 태그 추천(확장, MVP 아님): 등록할 때 서비스 이름, 설명, 선택한 카테고리를 보고 알맞은 태그를 추천한다(네이버 지식인의 카테고리 추천처럼). 등록자가 추천된 태그를 고르거나 직접 입력한다. 기존에 쓰인 태그 중 글자가 맞는 것을 추천하는 규칙 방식을 기본으로 하고, AI 방식은 확장으로 둔다.

구분: 확정(목록·순서·복수 선택, 태그 추천은 확장), 제안(최대 3개, 태그 추천 방식)

### 4.9 이용 형태와 지원 언어

서비스를 어떻게 이용할 수 있는지(이용 형태)와 서비스가 지원하는 언어를 분류에 포함한다.

| 기준 | 값 | 규칙 |
|---|---|---|
| 이용 형태 | 웹 서비스 / 오픈소스(확장) / (확장) 사이트 안에서 이용 | 서비스 링크가 있으면 "웹 서비스", GitHub 링크만 있으면 "오픈소스"(확장)이다. 웹 서비스에 GitHub 링크를 함께 입력하면 코드 아이콘이 표시되며, 이용 형태는 "웹 서비스"로 유지된다 |
| 지원 언어 | 한국어 / 영어 | 복수 선택, 기본값은 한국어. 서비스가 지원하는 언어이며 WEBTER 화면의 언어와는 별개 |

- 상세 페이지에는 `이용하기` 버튼(서비스 링크)을 두고, GitHub 링크가 있으면 코드 아이콘(`</>`)만 둔다. 사용자가 바로 즐기는 것이 WEBTER의 목적이므로 GitHub 연결은 눈에 띄지 않게 둔다. 제작자 본인의 GitHub 계정은 프로필의 외부 링크에, 서비스의 소스 저장소는 서비스 상세 페이지에 둔다.
- 필터에서 지원 언어로 서비스를 거를 수 있다. 이용 형태는 지금 고를 수 있는 값이 없으므로 필터로 두지 않고, 상세 페이지 소개 탭의 서비스 정보에만 표시한다.
- 내부 연결(확장)을 도입하면 상세 페이지에 설명 탭(미리보기 이미지)과 이용 탭(사이트 화면)을 두고 전환한다.

구분: 확정

### 4.10 오픈소스 서비스 (확장)

GitHub 링크만 있고 서비스 링크가 없는 서비스를 "오픈소스"로 받는다. 라이브러리, 도구 등 GitHub로 소스가 공개된 프로젝트가 해당한다. 개발자가 모이는 곳이라 수요가 없다고 할 수 없지만 일반 사용자에게는 낯설어서, 메인 기능이 아니라 옆으로 빼 둔 부가 영역으로 둔다. MVP는 아니다.

- **입구:** 화면 최상단 오른쪽에 코드 아이콘(`</>`)만 둔다. 설명을 붙이지 않아 일반 사용자에게는 눈에 띄지 않게 한다. 누르면 오픈소스 서비스 목록이 열린다.
- **영역 안:** 트렌딩·인기·최신과 카테고리로 탐색한다.
- **기본 노출:** 홈, 기본 목록, 검색에서는 오픈소스를 제외한다. 검색 필터에서 사용자가 직접 설정하면 오픈소스를 포함한다(이용 형태 필터를 두지 않으므로 포함 방식은 확장 때 다시 정한다).
- **버튼:** `이용하기`가 없고 GitHub 저장소로 연결한다.
- **집계 분리:** 오픈소스는 이용 집계를 하지 않는다. 실행 기준이 모호하기 때문이다. 좋아요와 저장만으로 인기 순위를 매기고(점수 = 좋아요 ×3 + 저장 ×5, 초기값), 웹 서비스와 순위를 따로 집계한다.
- **반응:** 오픈소스에도 좋아요, 저장, 리뷰를 적용한다. 내용은 웹 서비스와 같다.
- **등록 항목:** 오픈소스는 기기 지원과 가격을 받지 않는다(해당 없음). 서비스 용도, 프로젝트 유형, 등록 주체, 태그는 웹 서비스와 같이 받는다. 지원 언어는 받지 않는다(제안).
- 웹 서비스에 붙은 코드 아이콘의 클릭은 집계하지 않는다.

구분: 확정(방식·반응 적용·기기와 가격 제외), 제안(지원 언어 제외)

## 5. 탐색·노출

### 5.1 카드와 목록

- 카드형은 썸네일, 서비스 제목, 한 줄 소개, 좋아요 수, 저장 수를 표시한다. 목록형은 아이콘, 서비스 제목, 한 줄 소개, 좋아요 수, 저장 수를 표시한다. 제작자는 표시하지 않는다.
- 좋아요 수와 저장 수는 작은 아이콘과 숫자로 모바일을 포함해 항상 표시한다. 카드의 수치에는 별도의 반응 버튼을 붙이지 않는다.
- 사용자는 카드형과 목록형 중 하나를 골라 볼 수 있다.
- 데스크톱에서 카드·목록에 마우스를 올리면(또는 키보드로 포커스하면) 팝업이 아니라 카드 안에 평가 문구와 리뷰 수(예: "긍정적 (14)")와 `이용하기` 버튼이 나타난다. `이용하기`를 누르면 서비스 링크가 새 탭에서 열리고, 카드의 다른 부분을 누르면 상세 페이지로 이동한다. 사용 불가능한 서비스의 버튼은 비활성이다.
- 마우스를 올릴 수 없는 모바일에서는 카드의 `이용하기` 버튼을 생략하고(탭하면 상세로 이동), 평가 문구와 리뷰 수는 항상 표시한다.
- 서비스 상세 상단에는 서비스 용도 칩, 서비스 이름, 한 줄 소개, 이용하기 등 CTA, 통계만 둔다. 프로젝트 유형·기기 지원·가격·등록 주체·지원 언어·이용 형태는 소개 탭의 「서비스 정보」에 표시한다. 소개 탭에는 제작자 카드(프로필 사진·이름·한 줄 소개)를 두고, 누르면 제작자 프로필로 이동한다.
- 상세의 서비스 소개는 마크다운으로 렌더링하고 기본은 접힌 상태(상단만 표시)로 둔다. 글이 길 때만 「더보기/접기」가 활성이고, 짧으면 비활성이다. 접는 기준(360자 또는 10줄 초과)은 제안이다.
- 상세 하단에 「비슷한 서비스」를 표시한다(기획서 3.2의 연계 노출 효과). 공개된 서비스만 쓴다. 구분: 제안(화면 표현)
- 서비스 상세 링크를 공유하면 서비스 이름, 한 줄 소개, 썸네일이 미리보기로 보이게 하고(OG 태그), 상세 페이지에 링크 복사 버튼을 둔다. Instagram 등 SNS로 홍보할 때 쓰기 위해서다.

### 5.2 홈

트렌딩·인기·최신 서비스를 요약해서 보여 준다. 관심 카테고리를 설정했다면 해당 카테고리의 트렌딩·인기를 우선 보여 준다. 섹션의 순서와 구성은 화면설계에서 정한다. (미정)

### 5.3 필터

프로젝트 유형, 기기 지원, 가격, 등록 주체, 지원 언어, 사용 상태로 필터링한다. 이용 형태 필터는 두지 않는다. **서비스 용도는 필터 패널이 아니라 목록 제목 아래 가운데의 카테고리 줄(전체 + 8개, 3·2·2·1개씩 구분선으로 묶음)**에서 고르며, 가장 자주 쓰는 필터이기 때문이다. 모바일로 접속하면 "모바일 지원 서비스만 보기" 토글이 켜진 상태로 시작하고, PC에서는 토글을 보여 주지 않는다. 서비스 용도 카테고리는 4.8을 따른다. 같은 그룹 안에서는 하나라도 해당하면 포함하고 서로 다른 그룹은 모두 만족해야 보인다(제안).

### 5.4 검색

| 항목 | 정책 | 구분 |
|---|---|---|
| 일반 검색 | 서비스 이름, 설명(한 줄 소개와 상세 설명), 태그에 검색어가 포함된 서비스를 찾는다 | 확정 |
| 정렬 | 관련도 / 인기 / 최신 | 확정 |
| AI 자연어 검색 | **MVP(후순위).** 화면 디자인에는 처음부터 반영하고, 구현은 일반 검색을 먼저 완료한 뒤 한다. 일정이 부족하면 확장으로 미룬다. 문장으로 입력하면 AI가 의도를 분석해 서비스를 찾는다 | 확정 |
| AI 검색 사용 제한 | 도입할 때는 호출 비용을 고려해 사용 횟수를 제한한다. 비회원은 하루 3회, 회원은 하루 20회(초기값). 횟수를 모두 쓰면 자연스럽게 일반 검색으로 전환한다 | 확정(방식), 제안(횟수) |
| 검색 결과 없음 | 안내 문구와 인기 서비스를 보여 준다 | 확정 |

### 5.5 트렌딩과 인기

| 항목 | 정책 | 구분 |
|---|---|---|
| 트렌딩 | 최근 3일 동안의 점수 합이 높은 서비스 | 확정 |
| 인기 | 사용자가 기간(주간/월간/전체)을 골라 누적 점수로 정렬 | 확정 |
| 점수 | 이용하기 클릭 ×1 + 좋아요 ×3 + 저장 ×5 (초기값, 데이터를 보고 조정). 리뷰와 조회수는 점수에 넣지 않는다. 오픈소스(확장)는 이용 집계 없이 좋아요와 저장만으로 따로 집계한다(4.10) | 확정(지표), 제안(가중치) |
| 순위 표시 | 트렌딩·인기 목록의 카드·목록에 순위 배지를 표시한다 | 제안(화면 표현) |
| 정렬 표시 | 트렌딩·인기·최신은 화면 고유 집계 기준을 정렬로 고정해 표시하고(인기만 기간 선택), 관련도·인기·최신 정렬 선택은 검색 결과에만 둔다. 사이드바 카테고리는 최신 목록에 서비스 용도를 미리 선택한 상태로 이동한다 | 제안 |

## 6. 반응과 리뷰

### 6.1 반응 종류

- 좋아요: 회원만, 서비스당 한 번
- 저장: 회원만. 모바일에서 발견한 PC 전용 서비스를 나중에 이용하는 용도로도 쓴다
- 리뷰: 의견 글 + 평가 상태(추천 / 비추천 / 미설정). 스팀의 평가 방식을 참고한다
- 리뷰 추천/비추천: 다른 회원이 리뷰 자체에 남기는 반응(6.2). 서비스의 평가 비율·등급과 별개다
- 댓글: 리뷰와 별개로 서비스 상세에서 나누는 이야기(6.4). 평가·집계와 무관하다

### 6.2 리뷰 규칙

| 항목 | 규칙 | 구분 |
|---|---|---|
| 작성 조건 | 서비스를 이용했는지 확인하지 않는다. 외부 서비스라 이용 여부를 검증할 수 없다 | 확정 |
| 회원 | 서비스당 리뷰 1개. 평가 상태와 글을 수정·삭제할 수 있다 | 확정 |
| 비회원 | 평가 상태는 "미설정"만 가능하다. 같은 IP로 서비스당 1개를 작성할 수 있고, 수정은 불가하며 삭제는 관리자만 한다 | 확정 |
| 링크 | 리뷰에는 링크를 넣을 수 없다 | 확정 |
| 익명 설정 | 등록자가 서비스마다 두 가지를 따로 설정한다. (1) 비회원 리뷰 허용 (2) 회원의 익명 리뷰 허용. 기본값은 둘 다 비허용. 허용된 서비스에서는 회원이 리뷰마다 익명 처리 여부를 고른다 | 확정 |
| 주의 안내 | 익명을 허용하면 스팸, 비방, 욕설이 달릴 수 있음을 등록자에게 안내한다 | 확정 |
| 제작자 본인 | 자기 서비스에 좋아요·저장을 할 수 없다. 리뷰는 쓸 수 있고 "제작자" 표시가 붙는다. 평가 상태는 없으며 평가 집계와 점수에서 제외한다 | 확정 |
| 제작자 답글 | 서비스 제작자(등록자)만 다른 사람의 리뷰에 답글을 달 수 있다. 다른 사용자는 답글을 달 수 없다. 앱스토어의 개발자 응답처럼 리뷰당 1개를 제안하며, 답글도 신고와 관리자 삭제의 대상이다 | 확정(제작자만), 제안(리뷰당 1개) |
| 리뷰 추천/비추천 | 회원이 다른 사람의 리뷰에 추천 또는 비추천을 남길 수 있다. 본인 리뷰에는 불가, 리뷰당 한 번(바꾸기·취소 가능, 제안). 서비스 평가 비율·등급·인기 점수에는 넣지 않는다. 리뷰 목록은 추천순(기본)과 최신순을 토글로 고른다. 추천순은 추천 수가 많은 순이고 같으면 최신순이다(제안) | 확정(기능), 제안(세부) |
| 비회원 식별 | IP 주소로 같은 사람인지 구분한다. 원문 대신 해시로 저장하며 개인정보 처리방침에 수집 항목으로 적는다. **화면에는 디시처럼 IP 일부만 표시한다(IPv4 예: `123.45`). 전체 IP는 표시하지 않는다.** 중복 방지용으로는 전체 IP의 HMAC을 저장하고, 공개 표시용 일부 IP는 따로 저장한다(HMAC에서 원문·일부 IP를 복원하지 않는다, 제안). IPv6 표시 규칙·HMAC 키 관리·보관 기간은 미정이다. 일부 표시가 개인정보 검토를 모두 해결한다는 뜻은 아니므로 구현 전에 확인한다. 공용 와이파이·VPN에서는 구분이 부정확할 수 있다 | 표시 방식 확정(일부 표시, 법적 확인 필요), 저장 방식 제안 |

### 6.3 평가 등급

추천 비율 = 추천 수 / (추천 수 + 비추천 수). 미설정 리뷰는 비율에 포함하지 않는다.

| 조건 | 표시 | 구분 |
|---|---|---|
| 추천+비추천 5개 미만 | 평가 수 부족 | 확정 |
| 5~19개 | 긍정적 (비율 80% 이상) / 부정적 (19% 이하) / 복합적 (그 사이) | 제안 |
| 20개 이상 | 비율 80~100% 매우 긍정적, 70~79% 대체로 긍정적, 40~69% 복합적, 20~39% 대체로 부정적, 0~19% 매우 부정적 | 확정(구간), 제안(20개 기준) |
| 많은 리뷰 구간 | 스팀의 "압도적으로 긍정적/부정적"은 두지 않거나 100개 이상일 때만 적용 | 미정 |

숫자는 초기값이며 등록 서비스가 늘면 조정한다.

### 6.4 댓글

| 항목 | 규칙 | 구분 |
|---|---|---|
| 위치 | 서비스 상세의 탭: 소개 \| 리뷰 \| 댓글 | 확정 |
| 성격 | 리뷰와 별개의 이야기 공간. 평가 비율·등급·인기 점수에 영향을 주지 않는다 | 확정 |
| 작성 | 작성자(제작자) 외 다른 회원끼리도 댓글과 답글을 달 수 있다. 링크·개수 제한은 두지 않는다 | 확정 |
| 작성 권한 | 회원만 작성한다(비회원 허용 여부는 미정) | 제안 |
| 익명 | 서비스마다 익명 댓글 허용/비허용을 등록자가 정한다. 기본값은 비허용이다. 허용하면 회원이 댓글마다 익명으로 남길 수 있다 | 확정(설정), 제안(기본값) |
| 반응 | 추천·비추천은 없다 | 확정 |
| 신고 | 신고 가능. 같은 회원은 같은 댓글을 한 번만 신고할 수 있다(8) | 확정 |
| 답글 깊이·정렬 | 답글은 한 단계까지, 등록순으로 표시한다. 삭제한 댓글에 답글이 있으면 「삭제된 댓글입니다」로 남긴다 | 제안 |
| 수정·삭제 | 작성자가 마이페이지(내가 쓴 댓글)와 상세에서 수정·삭제한다 | 확정 |

## 7. 집계

| 항목 | 정책 | 구분 |
|---|---|---|
| 조회수 | 서비스 상세 페이지를 연 횟수. 화면에 표시만 하고 점수에는 넣지 않는다. 제작자 본인 조회는 제외 | 확정 |

| 이상 징후 대응 | 같은 회원 또는 같은 IP(해시)가 같은 서비스를 1분 안에 10회 이상 또는 5분 안에 20회 이상 클릭하면, 그 서비스의 클릭을 1시간 동안 집계에서 제외한다(다른 서비스에는 영향 없음). 클릭 기록은 남기며, 기준은 데이터를 보고 조정한다 | 확정 |

## 12. 미확정 사항

- 홈 섹션의 순서와 구성 (프로토타입 단계에서 결정)
- 카테고리 복수 선택 최대 개수
- 카드 썸네일의 정확한 비율
- 필수 등록 항목 구성, 정식 서비스 정의
- 평가 등급 구간 수치와 많은 리뷰 구간 적용 여부
- 자동 임시 비공개 임계값, 제작자 답글의 개수·수정 규칙
- 아이디 변경 횟수 제한
- 인기 점수 가중치, 하루 등록 개수, AI 검색 횟수
- 오픈소스 영역의 세부(지원 언어 등 그 밖의 등록 항목, 화면 구성)
- 사이드바 구조(현재 구조 유지, 추후 재검토)
- 댓글 세부(비회원 작성 허용 여부, 답글 깊이, 익명 허용 기본값), 리뷰 추천/비추천 세부(1인 1표 방식, 추천순 기준)
- 마크다운 소개의 접힘 기준·최대 길이·이미지 허용 여부
- 필터 결합 방식(같은 그룹 OR·그룹 사이 AND, 제안), 정렬 표시 방식(5.5)
- 비회원 리뷰 IP 일부 표시의 개인정보 요건과 IPv6 표시 규칙·HMAC 키 관리·보관 기간(15)
- 소셜 로그인 종류마다 별도 계정으로 처리하는 정책과 Supabase Auth의 동일 이메일 identity 자동 연결 동작의 충돌 해소(2.1)
- 내부 연결의 MVP 포함 여부
- AI 모델과 외부 API, 검색 방식
- 만 14세 미만 가입 제한 등 약관·개인정보 관련 법적 요건 (구현 전 확인)
- 웹게임의 등급분류 등 게임 관련 법적 요건 (링크 연결만 하는 경우의 적용 여부, 구현 전 확인)

## 13. 멘토 확인 사항

- 소셜 로그인만으로 서비스를 운영해도 되는지, 보안과 운영 측면에서 문제가 없는지
- 내부 연결(사이트 안에서 실행)의 MVP 포함 여부
- 비회원 IP 식별 방식이 개인정보 측면에서 적절한지
- 평가 등급과 인기 점수 산정 방식의 적정성
- 관리자 페이지 없이 운영자가 DB로 직접 처리하는 방식이 MVP 운영에 충분한지

## 14. 용어

- **서비스:** 개발자가 만든 웹 서비스. WEBTER에 등록되는 대상
- **이용하기:** 서비스 링크(실행 주소)를 새 탭에서 여는 버튼
- **오픈소스:** GitHub 링크만 있고 서비스 링크가 없는 서비스(확장)
- **이용 형태:** 웹 서비스 / 오픈소스(확장) / (확장) 사이트 안에서 이용. 입력한 링크로 정해진다
- **리뷰:** 서비스에 남기는 의견 글과 평가 상태(추천/비추천/미설정)
- **반응:** 리뷰, 좋아요, 저장(리뷰 추천/비추천은 리뷰에 대한 반응)
- **댓글:** 리뷰와 별개로 상세에서 나누는 이야기. 평가·집계와 무관
- **등록자:** 서비스를 등록한 회원
- **사용 상태:** 서비스를 지금 쓸 수 있는지 나타내는 상태(사용 가능/사용 불가능)
- **공개 상태:** 서비스가 목록에 노출되는지 나타내는 상태(공개/비공개, 임시 비공개 포함). 공개일 때는 화면에 표시하지 않는다

## 16. MVP 개발 우선순위

MVP 기능은 그대로 두고 **개발 순서**만 3단계로 나눈 것이다. 일정이 부족하면 3단계부터 확장으로 미룬다. 이 분류는 제안이며 개발하면서 조정한다.

| 단계 | 기능 | 의미 |
|---|---|---|
| 1단계 (핵심 흐름) | 소셜 로그인(구글·카카오)과 온보딩(약관 동의, 아이디·닉네임), 로그인 안내와 원래 페이지로 복귀, 서비스 등록(서비스 링크, 분류, 등록 시 확인 체크, 주소 검증), 홈(최신·인기 기본), 목록·카테고리·기본 필터, 일반 검색, 서비스 상세와 `이용하기`, 조회수·`이용하기` 클릭 기록(저장만), 좋아요·저장, 리뷰(추천/비추천/미설정), 제작자 프로필(기본 정보·외부 링크·서비스 목록), 마이페이지(내 서비스·저장·내 리뷰), 기본 반응형, 링크 공유 미리보기(OG)와 링크 복사, 약관·개인정보처리방침 페이지(임시) | 이것만 돼도 발표에서 시연할 수 있는 최소선 |
| 2단계 (완성도) | 평가 등급 표시(카드·목록·상세), 제작자 답글, 댓글, 리뷰 추천/비추천과 정렬(제안), 비회원 리뷰와 익명 설정(IP 해시), 관심 카테고리와 홈 우선 표시, 트렌딩, 카드·목록 보기 전환, 모바일 지원 필터 토글, 버전 기록, 신고(서비스·리뷰·답글·프로필)와 자동 임시 비공개, 사용 상태(사용 가능/불가능) | 있으면 설득력이 크게 올라가는 기능 |
| 3단계 (여유가 있으면) | AI 자연어 검색, GitHub 링크 입력과 코드 아이콘, 이상 징후 집계 제한, 인기 기간 선택, 마크다운 소개, 미리보기 이미지 최대 8장과 맞춤 방식(꽉 채우기 편집), 지원 언어 필터, 하루 등록 개수 제한 | 시간이 남을 때 |

특히 무거운 항목은 비회원 리뷰(IP 식별과 익명 설정), 이미지 맞춤 편집, 신고 자동 처리다.
